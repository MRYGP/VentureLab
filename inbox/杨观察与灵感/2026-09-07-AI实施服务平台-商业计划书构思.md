## 2026-09-09 审计与裁决

### 当前结论

本文保留为未经市场证据验证的构思原稿，不作为产品说明书、商业计划书或可行性报告使用。原稿主体不做静默改写，以便未来区分杨的原始观察、KIMI 的生成内容、Codex 的审计判断和真实外部证据。

当前值得保留的最窄假设是：

> AI 项目从实施开发者移交给长期维护者时，可能缺少结构化、可移交、可观测的运行档案；部分客户可能愿意为更低的接手成本和持续运行保障付费。

该表述仍为 `H`，尚无本文件内的真实维护付款、续约、扩单或流失材料支持。

### 结构性问题

- 原稿把企业需求发现、开发者撮合、低代码工具、技术资产管理、自动运维和承担 SLA 的托管服务捆成一个 MVP，实际是六组相互依赖的假设。
- 机会叙事依赖“项目高度非标”，规模叙事又依赖“项目高度标准化”。越能标准化，越可能被云厂商、SaaS 或垂直软件吸收；越非标，陌生维护员越难快速接手。
- “技术资产在平台，客户绕不过”不能直接作为护城河。客户数据、Prompt、业务规则、配置和运行记录的权属、授权、导出、删除、隔离和责任边界均为 `Ø`。未来若重启，应优先检验“客户可导出、仍愿因服务价值续费”，而不是用资料扣留制造退出障碍。
- 平台若承担验收、资金托管、质量担保、数据保管、故障响应和持续维护，就不再只是轻撮合平台；相应的安全、合规、保险、责任与人力成本尚未进入模型。

### 财务口径审计

- 原稿第 9.1 节若把平台收入定义为项目服务费 10,000 元加首年维护费 18,000 元，则 18,500 元毛利对应约 `66.1%`，不是文中的 `16.8%`；若以客户总支出 118,000 元为分母，则约为 `15.7%`。必须先决定平台按代理净额还是主责方总额记账。
- 第二年写“累计维护中项目 400 个、月费均价 1,500 元”，即使 400 个项目全部服务满 12 个月，收入上限也只有 720 万元，低于预测的 1,134 万元。
- 第三年 1,200 个项目按相同口径的全年收入上限为 2,160 万元，低于预测的 4,147 万元。
- 维护转化率、续费率、一名维护员管理 50—80 个项目、五分钟理解项目和维护边际成本极低，当前均为 `H`，不能用相互引用的方式组成盈利证明。

### 重新进入研究或项目的条件

当前不先评审整个平台的技术可行性。若杨以后明确重启，应先进行一次不改变方向 B 的有界研究：

1. 只选一个目标用户、一个业务场景和一个具体服务 SKU；
2. 找到至少一条真实实施付款材料，并优先核验是否另付维护费、维护边界及续约行为；
3. 同时保留一个自行维护、换供应商或停止使用的反例；
4. 首轮仅使用公开材料，人工上限 4 小时，不联系真人；
5. 仍无维护付款或续约行为时停止，不继续扩写平台架构；

## 1. 项目概述

### 1.1 一句话定义

> **一个连接 AI 实施开发者（装修队）与企业客户，通过强制沉淀技术资产实现标准化交付与持续维护订阅的 B2B 服务平台。**

### 1.2 核心命题

当前大模型 API 已经白菜价，但**"把模型接入业务系统"这件事极度非标、极度依赖个人经验、极度缺乏售后维护**。云厂商卖砖（模型API），但不会帮客户砌墙（业务集成）。

本平台不做模型、不卖算力，而是做**"AI 工程实施的标准化平台"**——让装修队有工具、有标准、有客源；让企业客户有交付质量保障、有可持续的维护服务。

### 1.3 与现有模式的区别

| 对比维度 | 传统外包公司 | 云厂商（火山/阿里） | 猪八戒等撮合平台 | **本平台** |
|---|---|---|---|---|
| 资产归属 | 装修队带走 | 云资源归厂商 | 无资产沉淀 | **平台沉淀技术资产** |
| 维护能力 | 依赖原团队 | 标准化产品，不做定制 | 无维护 | **专职维护团队+自动化** |
| 客户锁定 | 弱（人走了就断了） | 强（云生态锁定） | 无 | **强（技术资产在平台）** |
| 规模效应 | 无（每个项目从零开始） | 有（算力规模） | 无 | **有（资产复用+自动化）** |
| 商业模式 | 项目制，手停口停 | 云资源租赁 | 撮合抽成 | **项目费+维护订阅** |

### 1.4 目标市场

- **首期目标**：年 IT 预算 20-200 万的中小企业
- **场景聚焦**：AI 客服、AI 知识库、AI 内容生成、AI 合同/文档审查
- **地域**：中国大陆（合规可控）

## 2. 市场痛点与机会

### 2.1 客户侧痛点

**痛点 1：买了 API，但不会用**

> 企业花 5000 元/月买了 DeepSeek API，但不知道怎么做 RAG、怎么写 Prompt、怎么搭工作流。10 人技术团队里，可能只有 1 个人懂一点，但不够深。

**痛点 2：项目交付后无人维护**

> 找外包团队 8 万做了一个 AI 客服，3 个月后：模型厂商更新了版本，输出格式变了，系统报错；知识库里的产品信息过时了，AI 开始胡说八道；原开发团队联系不上，或者报价翻倍。

**痛点 3：换供应商成本极高**

> 系统里沉淀了 5000 条知识库、20 版 Prompt、17 条业务规则，全部散落在原开发者的个人电脑和脑子里。换个人维护等于"考古发掘"。

### 2.2 开发者侧痛点

**痛点 4：好开发者接不到好活**

> 懂 Prompt 工程、懂 RAG、懂 Agent 编排的开发者是稀缺资源，但他们没有稳定的获客渠道，在闲鱼/朋友圈接单，价格低、需求乱、回款难。

**痛点 5：被维护拖累，无法专注新项目**

> 一个开发者同时维护 5 个老项目，每个项目每月出 2-3 个小问题，占掉 40% 的时间。但他不敢不接维护，因为老客户是他的主要收入来源。

### 2.3 市场机会量化

| 指标 | 数据 | 来源 |
|---|---|---|
| 中国中小企业数量 | 5200 万+ | 工信部 |
| 已使用大模型的企业占比 | < 15% | 行业调研 |
| 企业 AI 落地主要障碍 | "缺乏技术人才"占 67% | 艾瑞咨询 |
| 中小企业 AI 项目平均预算 | 5-30 万 | 行业调研 |
| 维护续费率（传统外包） | < 20% | 行业经验 |

**机会窗口**：2026-2028 年，大模型能力已足够成熟、API 价格已足够低，但"最后一公里"的交付和维护服务极度匮乏。

### 3.2 收入来源

| 收入项 | 收费对象 | 定价模式 | 占比目标 |
|---|---|---|---|
| **项目匹配服务费** | 企业客户 | 项目总价的 8%-12% | 20% |
| **开发者认证/培训费** | 开发者 | 一次性 500-2000 元 | 5% |
| **维护订阅费** | 企业客户 | 月费 300-3000 元/项目 | **60%** |
| **增值服务** | 企业客户 | 按次计费（紧急响应、重大升级） | 15% |

**核心逻辑**：项目交付是获客手段，维护订阅是利润中心。

### 3.3 成本结构

| 成本项 | 说明 | 占比目标 |
|---|---|---|
| 平台研发 | 工具链、资产库、自动化系统 | 25% |
| 维护团队人力 | 专职维护员的工资 | 30% |
| 获客成本 | 企业客户的市场推广 | 20% |
| 运营支撑 | 客服、法务、财务 | 15% |
| 基础设施 | 云服务器、数据库、监控 | 10% |

### 3.4 关键假设

- **项目交付周期**：平均 4-6 周
- **项目均价**：8-15 万
- **维护订阅转化率**：70%（项目交付后签维护合同）
- **维护续费率（年化）**：80%
- **单个维护员管理项目数**：50-80 个（L1/L2 自动化后）
- **开发者留存率**：年化 75%

## 4. 平台角色与生态分工

### 4.1 三方角色定义

#### 角色 A：企业客户（业主）

- **特征**：有 AI 落地需求，但缺乏技术人才或不想长期养技术团队
- **核心诉求**：系统稳定运行、出问题有人兜底、成本可预期
- **付费意愿**：项目费一次性可接受，但更希望"按月付费、有人管"

#### 角色 B：认证开发者（装修队）

- **特征**：懂 AI 工程实施（Prompt、RAG、Agent、工作流），但缺乏稳定客源
- **核心诉求**：有活干、回款快、不用管维护的烂摊子
- **与平台关系**：非雇佣关系，项目制合作，按项目结算

#### 角色 C：平台方

- **核心职能**：
  1. **标准制定者**：定义交付标准、资产沉淀格式、质量验收清单
  2. **匹配撮合者**：根据项目需求匹配最合适的开发者
  3. **资产管理者**：强制沉淀所有技术资产，建立"数字孪生"
  4. **维护服务者**：专职团队提供持续运维，不依赖原开发者

### 4.2 价值流转图

```
企业客户 ──→ 发布需求 + 预付项目款
    │
    ↓
平台 ──────→ 匹配认证开发者 + 提供标准化工具
    │
    ↓
认证开发者 ──→ 使用平台工具交付项目
    │
    ↓
平台 ──────→ 验收项目 + 强制资产入库
    │
    ↓
企业客户 ──→ 验收通过 + 签维护订阅
    │
    ↓
平台维护团队 ──→ 持续运维（基于资产库）
    │
    ↓
企业客户 ──→ 按月/年付维护费
```

### 4.3 开发者激励机制

| 激励项 | 具体设计 |
|---|---|
| **获客支持** | 平台派单，开发者不用自己找客户 |
| **工具支持** | 免费提供标准化开发工具、测试环境、模板库 |
| **收入保障** | 项目款平台托管，验收后自动结算，无拖欠 |
| **维护解脱** | 项目交付后，维护由平台接管，开发者可以接新项目 |
| **等级体系** | 根据交付质量、客户评分、资产完整度升级，高等级优先派单 |
| **培训认证** | 平台提供 AI 工程实施培训，通过认证才能接单 |

**关键约束**：开发者必须使用平台提供的工具进行开发，所有配置、参数、知识库必须实时同步到平台资产库。这是强制性的，不接受就用不了平台工具。

### 5.2 部署架构

## 6. 核心功能模块

### 6.1 模块 1：项目管理系统

**功能清单**：

- **需求发布**：企业客户填写标准化需求模板（场景类型、预算范围、时间要求、技术约束）
- **智能匹配**：根据项目类型、预算、复杂度，自动匹配 2-3 名认证开发者
- **进度跟踪**：里程碑式项目管理（需求确认 → 方案设计 → 开发实施 → 测试验收 → 资产入库）
- **质量验收**：平台提供标准化验收清单，客户+平台双重验收
- **资金托管**：项目款由平台托管，分阶段释放（30% 启动 + 40% 中期 + 30% 验收）

**技术要点**：
- 需求模板必须结构化（JSON Schema），不能是自由文本
- 匹配算法基于开发者历史评分、技能标签、当前负载
- 验收清单与资产入库联动，资产不完整不能通过验收

### 6.2 模块 2：开发者工具链（核心差异化）

**功能清单**：

- **可视化 Prompt 编辑器**：支持变量、版本管理、A/B 测试
- **RAG 知识库构建器**：支持多数据源导入（PDF/Word/网页/数据库）、自动分块、向量生成
- **Agent 工作流编排器**：拖拽式搭建多步骤 AI 工作流（条件分支、工具调用、人工审核节点）
- **模型路由配置器**：配置多模型切换策略（效果优先/成本优先/平衡模式）
- **沙箱测试环境**：一键创建隔离测试环境，模拟真实业务数据
- **实时同步引擎**：所有配置变更实时同步到平台资产库

**关键设计原则**：

> **开发者必须在平台工具链内完成全部开发工作。任何在本地 IDE 里写死、不通过平台工具配置的内容，都无法通过验收。**

这不是为了限制开发者，而是为了确保**技术资产的可沉淀、可维护、可交接**。

### 6.3 模块 3：技术资产管理系统

**功能清单**：

- **资产全景视图**：每个项目的全部技术资产一览（模型配置、Prompt 库、知识库、工作流、业务规则、API 映射）
- **版本控制**：所有资产的变更历史、变更人、变更原因
- **资产模板库**：沉淀可复用的资产模板（行业通用 Prompt、常见知识库结构、标准工作流）
- **资产健康度评分**：完整性、规范性、可维护性自动评分
- **资产导出/导入**：支持标准化格式（JSON/YAML）的导入导出

### 6.4 模块 4：维护自动化系统

**功能清单**：

- **L1 自动监控**：
  - 模型 API 可用性监控（响应时间、错误率、限流状态）
  - 知识库新鲜度监控（数据源更新自动检测）
  - Prompt 效果监控（输出质量评分、用户反馈统计）
  - 成本监控（Token 消耗、费用趋势、异常告警）

- **L2 自动修复**：
  - 模型 API 故障自动切换备用模型
  - 知识库过期内容自动标记待更新
  - 常见异常自动重试/降级

- **L3 人工工单**：
  - 复杂问题自动生成工单，分配给维护员
  - 工单与资产库联动，维护员 5 分钟内可了解系统全貌
  - 工单处理记录自动沉淀为知识库

- **L4 主动优化**：
  - 每月生成《系统优化报告》（效果分析、成本分析、升级建议）
  - 主动推送模型版本更新、Prompt 优化建议

### 6.5 模块 5：计费结算系统

**功能清单**：

- **项目费结算**：按里程碑自动分账（平台服务费 + 开发者报酬）
- **维护订阅管理**：月费/年费订阅、自动续费、到期提醒
- **增值服务计费**：紧急响应按次计费、重大升级按工时计费
- **开发者结算**：每月自动结算，支持银行卡/支付宝
- **财务报表**：项目收入、维护收入、成本、毛利自动统计

## 7. 技术资产沉淀机制（核心壁垒）

### 7.1 什么是"技术资产"

技术资产不是源代码，而是**"让系统可维护、可交接、可优化的结构化配置信息"**。

具体包括：

| 资产类型 | 具体内容 | 沉淀方式 |
|---|---|---|
| **模型配置资产** | 使用的模型列表、路由策略、参数设置、备用模型配置 | 通过模型路由配置器自动生成 |
| **Prompt 资产** | 所有 Prompt 模板、变量定义、版本历史、A/B 测试结果 | 通过 Prompt 编辑器自动生成 |
| **知识库资产** | 向量数据库结构、分块策略、元数据、数据源映射、更新规则 | 通过 RAG 构建器自动生成 |
| **工作流资产** | Agent 工作流定义、节点配置、条件规则、工具调用映射 | 通过工作流编排器自动生成 |
| **业务规则资产** | 业务逻辑规则（如"退款类问题必须转人工"）、阈值设置、异常处理策略 | 通过规则配置器填写 |
| **集成映射资产** | 与客户业务系统的 API 映射、数据格式转换规则、认证配置 | 通过集成配置器填写 |
| **效果基准资产** | 系统上线时的效果基准（准确率、延迟、成本），作为后续优化对比 | 验收时自动记录 |

### 7.2 资产沉淀的技术实现

**① 配置即代码（Config as Code）**

所有资产以结构化格式（JSON/YAML）存储，支持版本控制、差异对比、回滚恢复。

```yaml
# 示例：模型路由配置资产
model_routing:
  project_id: "proj_202609_001"
  version: "v1.2.3"
  updated_at: "2026-09-07T10:30:00Z"
  updated_by: "dev_zhangsan"

  strategies:
    - name: "效果优先"
      priority: 1
      models:
        - provider: "deepseek"
          model: "deepseek-chat-v3"
          weight: 0.7
        - provider: "kimi"
          model: "kimi-k2.5"
          weight: 0.3
      fallback:
        - provider: "qwen"
          model: "qwen-max"

    - name: "成本优先"
      priority: 2
      models:
        - provider: "deepseek"
          model: "deepseek-chat-v3"
          weight: 1.0
      max_cost_per_1k_tokens: 0.02

  rules:
    - condition: "query_length > 1000"
      action: "route_to_long_context_model"
    - condition: "category == '退款'"
      action: "route_to_human"
```

**② 强制校验机制**

验收时，系统自动校验资产完整性：

| 校验项 | 校验规则 | 不通过后果 |
|---|---|---|
| 资产完整性 | 所有必填资产类型是否都已提交 | 验收不通过 |
| 资产规范性 | 是否符合平台定义的 Schema | 退回修改 |
| 资产一致性 | 配置之间是否有冲突（如引用了不存在的 Prompt） | 自动检测并提示 |
| 资产可运行性 | 导入沙箱后是否能正常运行 | 验收不通过 |

**③ 资产复用机制**

- 开发者可以引用平台资产模板库中的公共模板
- 相似项目的资产可以"克隆"并修改，减少重复工作
- 优质资产经审核后可以进入模板库，开发者获得奖励

## 8. 维护订阅体系

### 8.1 维护服务分级

| 级别 | 服务内容 | 响应时间 | 月费范围 | 目标客户 |
|---|---|---|---|---|
| **基础版** | 自动监控 + 月度报告 + 邮件支持 | 24h | 300-800 元 | 小型项目、非核心业务 |
| **标准版** | 基础版 + 工单支持 + Prompt 优化建议 + 知识库季度更新 | 4h | 800-2000 元 | 中型项目、核心业务 |
| **高级版** | 标准版 + 7x24 紧急响应 + 专属维护员 + 月度优化会议 + 模型版本升级服务 | 1h | 2000-5000 元 | 大型项目、关键业务 |
| **定制版** | 高级版 + 私有化部署 + 驻场支持 + 定制开发 | 协商 | 5000+ 元 | 国企、金融、医疗 |

### 8.2 维护自动化深度

**L1 自动监控（零人力）**

- 模型 API 健康检查（每 5 分钟）
- Token 消耗异常检测（同比/环比）
- 知识库新鲜度扫描（每日）
- 输出质量评分（基于规则+轻量模型）

**L2 自动修复（零人力）**

- API 故障自动切换备用模型（< 30 秒）
- 常见错误自动重试（3 次指数退避）
- 知识库过期内容自动标记
- 成本超阈值自动告警并建议降级策略

**L3 人工处理（维护员介入）**

- 复杂故障诊断（基于资产库快速定位）
- Prompt 效果调优（基于 A/B 测试数据）
- 知识库内容更新（基于客户提供的新资料）
- 业务规则调整（基于客户反馈）

**L4 主动优化（维护员+算法）**

- 每月生成《系统健康报告》
- 模型性价比分析（是否有更便宜模型可替代）
- Prompt 压缩优化（减少 Token 消耗）
- 工作流重构建议（基于运行数据分析）

## 9. 财务模型与盈利预测

### 9.1 单位经济模型（Unit Economics）

**以一个标准项目为例**：

| 项目 | 金额（元） | 说明 |
|---|---|---|
| **项目总收入** | 100,000 | 企业客户支付的项目款 |

| 开发者报酬（80%） | 80,000 | 开发者收入 |
| 资金托管成本（0.5%） | 500 | 支付通道费 |
| **项目毛利** | **9,500** | 平台项目阶段毛利 |
| | | |
| **维护订阅（标准版）** | 1,500/月 | 客户持续付费 |
| 维护员人力成本 | 600/月 | 1 人管 50 个项目，月薪 30,000 |
| 自动化系统摊销 | 100/月 | 研发成本分摊 |
| 基础设施成本 | 50/月 | 云资源 |
| **维护月毛利** | **750** | 维护阶段月毛利 |
| **维护年毛利** | **9,000** | 维护阶段年毛利 |
| | | |
| **项目全生命周期毛利** | **18,500** | 项目费毛利 + 首年维护毛利 |
| **毛利率** | **16.8%** | （项目费 9.5% + 维护费 50% 综合） |

| 维护订阅收入（万） | 151 | 1,134 | 4,147 |
| **总收入（万）** | **1,351** | **4,734** | **13,747** |
| | | | |
| 项目成本（开发者报酬） | 960 | 2,880 | 7,680 |
| 维护人力成本（万） | 72 | 216 | 576 |
| 研发成本（万） | 300 | 400 | 600 |
| 获客成本（万） | 200 | 400 | 800 |

## 11. 风险识别与对策

### 11.1 技术风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 工具链不成熟，开发者抵触 | 开发者不愿意用平台工具，资产沉淀失败 | 先从小功能切入，证明工具能提升效率；给予使用奖励；不接受工具的不予认证 |
| 资产沉淀格式频繁变更 | 历史资产不兼容，维护困难 | 版本化管理；Schema 变更必须向后兼容；提供迁移工具 |
| 维护自动化效果不佳 | 维护员工作量不降反升，成本失控 | 分阶段上线自动化功能；先监控后修复；设置人工兜底机制 |

### 11.2 商业风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 云厂商推出类似服务 | 被大厂降维打击 | 聚焦"非标定制+维护服务"，大厂不愿做的脏活；建立开发者生态壁垒 |
| 开发者质量参差不齐 | 项目交付质量差，客户投诉 | 严格认证+等级体系+项目保证金；建立黑名单机制 |
| 维护续费率低于预期 | 收入模型不成立 | 维护费包含在项目费中（捆绑销售）；提供不可替代的主动优化服务 |
| 客户绕过平台直接找开发者 | 平台被架空 | 技术资产在平台，客户绕不过；维护服务只有平台能提供 |

### 11.3 合规风险

| 风险 | 影响 | 对策 |
|---|---|---|
| AI 生成内容合规问题 | 平台作为服务方被追责 | 内置内容安全审查；所有输出留痕审计；合同中明确责任边界 |
| 数据安全/隐私问题 | 客户数据泄露，信任崩塌 | 私有化部署选项；数据加密传输和存储；通过等保/ISO27001 认证 |
| 模型厂商政策变化 | 模型 API 涨价、限流、关闭 | 多模型策略；资产库支持快速切换模型；与多家模型厂商建立合作关系 |

### 11.4 团队风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 核心技术人员流失 | 产品开发停滞 | 技术文档完善；关键岗位 AB 角；股权激励 |
| 维护团队扩张跟不上 | 项目积压，客户满意度下降 | 维护自动化优先投入；维护员培训体系标准化 |

## 12. 附录

### 12.1 术语表

| 术语 | 定义 |
|---|---|
| **RAG** | Retrieval-Augmented Generation，检索增强生成，一种让大模型基于外部知识库回答问题的技术 |
| **Prompt** | 提示词，给大模型的输入指令，决定输出质量 |
| **Agent** | 智能体，能够自主规划、调用工具、完成多步骤任务的 AI 系统 |
| **向量数据库** | 专门存储和检索高维向量（文本/图像的数学表示）的数据库 |
| **Token** | 大模型处理文本的最小单位，也是计费单位 |
| **模型路由** | 根据策略自动选择使用哪个大模型处理请求 |
| **A/B 测试** | 对比两种方案效果的方法，常用于 Prompt 优化 |

### 12.2 竞品分析

| 竞品 | 类型 | 优势 | 劣势 | 我们的差异化 |
|---|---|---|---|---|
| 硅基流动 | 模型 API 聚合 | 价格便宜、模型多 | 只做 API 分发，不做实施和维护 | 我们提供完整的实施+维护服务 |

## 一、90 秒版本

`F-P·杨观察`：真正值得借鉴的不是“拿便宜模组做一个场景产品”，而是在设计硬件时就假定后面存在计算、模型或反馈，使旧硬件可以故意少一点、糙一点、弱一点，甚至形成过去无法存在的机器。

两份机制侦察与方舟内部活体参照没有证明“AI 重构硬件会产生大量适合杨的机会”，但把四个构思视角修正得更清楚：

1. **维持关键物理交互条件**：人或粗机械负责大范围动作，局部闭环维持位置、角度、距离、压力、耦合或流量；
2. **采集条件与覆盖质量闭环**：不替代专家判断，先让设备发现“没有测好”并要求当场补齐；
3. **主动测量与真实补采**：在完成必要物理覆盖后，根据已有信息决定下一次位置、角度、倍率、照明、频率或传感方式；
4. **可控激励与计算感知**：主动施加已知刺激，使原本难以观察的状态产生可测响应，再决定是否改变下一次激励。

本文件把四个结构各展开两个产品构思，共 8 个。它们横跨较近的专业工具改造、中期新硬件和长期主动测量系统，不做跨量纲总排名。

最重要的共同边界是：**计算没有消除精度、信息和责任，只是把它们从大机架、专家手艺或全量采集，转移到定位基准、标定、补采、软件维护和失效处理。模型“很确定”也不能证明物理上已经充分观察。**

## 二、共同设计纪律

每个构思都必须同时回答：

- 旧设备靠什么承重；
- 新设备具体少了什么、放松了什么；
- 计算接走哪部分工作；
- 新增了什么、牺牲了什么；
- 失败时是否能停下、退化或要求人工确认；
- 用户购买的是任务结果，还是只觉得技术新奇。

本轮不预设必须使用机器学习。经典视觉、控制、信号处理可以完成时，不因“AI”叙事改用更复杂模型。

对测量类构思还必须依次区分：必要区域是否覆盖、本次采集条件是否合格、模型是否不确定、是否需要取得新的真实信息、下一次物理测量应改变什么。不得用模型置信度代替覆盖和信号质量。

## 三、路线 A：维持关键物理交互条件

### A1｜手持式大幅面精准放样／标线器

| 字段 | 当前构思 |
| --- | --- |
| 用户／场景 | `H`：船厂、机电安装、展陈施工或特殊装修人员，需要在立面、双曲面、狭小空间或大型非平面结构上标出孔位、切割线、安装轮廓或连续曲线 |
| 当前替代 | 卷尺＋墨线／粉笔；激光投线；纸质模板；全站仪放点；墙面打印机或大型数控设备 |
| 主要变化 | 人负责把设备沿大致路径移动，视觉标记／相机／惯导估计全局位置和曲面法向，小行程执行器修正落点，并维持标线头与表面的距离、角度或接触压力，使机器人／全站仪难以布设的非平面任务不再需要同尺寸机架或完整模板 |
| 已有部分 | `I`：Shaper Origin 已证明“人做大行程＋小执行器纠偏”可以成为商品；HP SitePrint 已覆盖配合全站仪的平整楼面机器人放样，A1 的差异已收窄到立面、曲面、狭小空间和低布设负担。手持等价方案仍为 `Ø` |
| 计算角色 | 视觉定位、曲面／轨迹配准、法向和距离估计、局部闭环控制；首版未必需要 ML |
| 我方可能控制 | 结构、定位基准、不同表面耗材、校准流程、施工数据格式与工作流 |
| 新增／牺牲 | 新增定位标记、相机标定、表面适应和耗材；牺牲完全无人值守，操作者仍需推行 |
| 最大未知 | 是否必须先取得精确 3D 模型；现场布基准和校准是否比人工量线更费时；遮挡后的定位恢复、曲面法向误差和大尺度累计误差能否控制 |
| 可推翻条件 | 若建模／布设／校准时间加返工风险不低于现有激光、模板或人工放样，或目标曲面已有等价可得的投影／机器人方案，则该差异不值得选择 |
| 依赖层级 | `H·中期定制硬件＋控制`；不计商业进展 |

### A2｜手持式曲线密封胶／胶黏剂轨迹助手

| 字段 | 当前构思 |
| --- | --- |
| 用户／场景 | `H`：车身维修、门窗安装、船舶舾装、卫浴施工人员，需要沿弯曲接缝打出连续、均匀且位置准确的胶线 |
| 当前替代 | 熟练工手持胶枪＋目测；遮蔽胶带；专用导轨；固定机器人或龙门点胶机 |
| 主要变化 | 人负责粗略沿缝移动，摄像头识别接缝，小范围喷嘴机构修正横向位置；系统同时维持喷嘴距离／接触压力，并根据推行速度、胶材温度或黏度调节出胶量，使“全行程机器人”降成“手持粗移动＋局部工艺状态闭环” |
| 已有部分 | 自动点胶和视觉跟踪均已成熟；手持工具中是否已有等价闭环产品为 `Ø` |
| 计算角色 | 接缝跟踪、距离／压力／速度估计、局部纠偏与流量控制；经典视觉和规则控制可作为基线 |
| 我方可能控制 | 喷嘴机构、胶材参数库、可清洁流道、校准与不同工艺的验收标准 |
| 新增／牺牲 | 新增堵胶、清洗、黏度变化、耗材适配和视觉遮挡；设备不能替代基层处理、打底和最终压缝 |
| 最大未知 | 轨迹、距离、压力和出胶量中哪项真正造成返工；还是表面准备和收口手艺才是瓶颈；闭环改善是否足以抵消清洗维护 |
| 可推翻条件 | 若普通工人借助简单导嘴／胶带已能稳定达到验收要求，主要返工来自基层和收口，或胶材变化让自动控制频繁失效，则不值得增加闭环硬件 |
| 依赖层级 | `H·中期定制硬件＋工艺数据` |

## 四、路线 B：采集条件与覆盖质量闭环

### B1｜建筑渗漏／保温异常的引导式巡检棒

> 处置：`保留为普通 B 线构思但移出 LT-01 核心`。现有热像＋测湿整机已覆盖主要硬件组合，剩余差异主要在采集条件、覆盖和证据流程。

| 字段 | 当前构思 |
| --- | --- |
| 用户／场景 | `H`：验房师、物业维修、防水维修人员，在墙面、顶棚、窗边和管线附近寻找渗漏、冷桥或保温异常，并需要留下可复查的证据 |
| 当前替代 | 热像仪、湿度计、含水率仪分别使用；靠经验决定扫哪里、距离和角度；拍零散照片后人工写报告 |
| 主要变化 | 设备先检查墙面温差、观察角度、反射、距离、分辨率和覆盖是否满足观察条件；发现可疑或未充分观察的区域后要求贴近测湿／复拍，并自动把测点和现场图对应。第一版只帮助“采得完整、可比较”，不自动宣称漏水原因 |
| 已有部分 | FLIR MR277 等产品已把热像引导、测湿与记录连接起来；手机热像附件、验房 App 和报告软件也已存在。剩余差异收窄为覆盖地图、漏扫／条件不足提示和可重复定位，是否等价可得仍需定向核验 |
| 计算角色 | 采集质量检查、覆盖地图、条件提醒、补测建议；识别模型只作辅助，不替代最终判断 |
| 我方可能控制 | 巡检流程、测点定位、跨传感器校准、报告证据链和服务标准 |
| 新增／牺牲 | 新增多传感器标定、环境条件记录、责任边界和报告维护；牺牲“拿起热像仪随手看”的简单性 |
| 最大未知 | 专业人员是否真的因漏扫和证据整理损失时间；新手生成的材料是否会被客户、维修方或保险方信任 |
| 可推翻条件 | 若专业用户用现有热像仪＋测湿仪即可低成本完成可靠闭环，或新手即使被指导也无法获得可用证据，则产品价值不足 |
| 依赖层级 | `H·普通 B 线近中期现成模组＋流程软件＋少量结构`；不再作为 LT-01 强硬件重构样本 |

### B2｜二手车漆面／车身检查的引导式测量套件

> 处置：`关闭当前版本`。带 App 的漆膜仪已经覆盖车身分区、逐点引导、读数同步、热图和报告；仅增加视觉自动绑定具体测点，现阶段差异过薄。以下原构思保留用于解释关闭原因。

| 字段 | 当前构思 |
| --- | --- |
| 用户／场景 | `H`：小型二手车商、流动检测员或高价值二手车买家，需要系统检查漆膜厚度和车身表面，但容易少测、测错位置或无法证明覆盖完整 |
| 当前替代 | 手持漆膜仪随机点测；经验判断色差与缝隙；委托检测门店；查看维修记录 |
| 主要变化 | 手机视觉识别车身区域并引导测量网格，漆膜仪读数自动绑定到具体位置；系统提示遗漏、异常复测和左右对称比较，输出覆盖地图。它只说明“哪里异常／证据不足”，不自动断言事故原因 |
| 已有部分 | NexPTG 等带 App 的漆膜仪已提供车身分区、测量引导、照片／读数组织和 PDF 报告；国产产品也存在车型／部位选择和蓝牙同步。只剩视觉自动定位到更具体测点的差异，是否改变任务为 `Ø` |
| 计算角色 | 位置绑定、覆盖检查、异常复测与证据组织；经典规则可先行，ML 不是前置条件 |
| 我方可能控制 | 车型表面分区、测量流程、设备连接、报告标准与历史数据 |
| 新增／牺牲 | 新增车型识别、曲面定位误差、设备兼容和金融／交易责任；检测时间可能上升 |
| 最大未知 | 用户是否愿意完成足够多测点；定位精度能否支持复测；专业检测的低价格是否已经消除独立工具空间 |
| 可推翻条件 | 若人工随机点测已经足以支撑交易，或定位与车型差异导致数据无法复用，则“完整覆盖”不会产生足够价值 |
| 依赖层级 | `关闭当前版本`；只有出现非接触快速扫描、主动选择下一测点或其他采集架构变化时才重新召回 |

## 五、路线 C：主动测量与真实补采

### C1｜电子维修用自适应复检显微台

| 字段 | 当前构思 |
| --- | --- |
| 用户／场景 | `H`：手机、电脑、无人机和小家电维修店，检查 PCB 焊点、连接器、腐蚀、异物和返修质量 |
| 当前替代 | 技师用显微镜逐区查看；拍照放大；高价工业 AOI；故障后再靠电测定位 |
| 主要变化 | 第一层先保证板面覆盖、对焦、曝光、反光和区域定位合格；第二层才把“不确定、疑似异常或与参考板差异大”的区域送到电动载台复拍，并切换倍率、焦点和照明角度。设备输出待人工确认的复检队列，不直接判定维修方案 |
| 已有部分 | 数码显微镜、电动载台、焦点堆栈和工业 AOI 均成熟；面向维修店而非产线的等价自适应产品为 `Ø` |
| 计算角色 | 覆盖与图像质量检查；变化检测和不确定性估计；主动选择下一视野、焦点与照明；必须允许拒绝判断 |
| 我方可能控制 | 小型载台、照明方式、维修板参考数据、补拍策略、技师反馈闭环 |
| 新增／牺牲 | 新增载台精度、参考板数据、误报队列和设备适配；可能比人工扫板更慢 |
| 最大未知 | 小店的板型极其分散，是否存在足够重复性；技师真正耗时是否在观察而非电测和拆装 |
| 可推翻条件 | 若保证“拍得完整、清楚、可定位”仍不能减少无效复查，或缺少参考数据时误报过多、熟练技师肉眼扫描明显更快，则主动显微不会改善任务 |
| 依赖层级 | `H·中期定制载台＋视觉模型` |

### C2｜复杂曲面无损检测的分层采集闭环

| 字段 | 当前构思 |
| --- | --- |
| 用户／场景 | `H`：船厂、复合材料维修、压力设备或大型结构检测人员，在狭小空间和曲面上进行超声／声学／热激励检测 |
| 当前替代 | 按固定网格全量扫查；机械扫查架／爬行器；技师凭经验反复扫可疑处；事后发现数据不足再返场 |
| 主要变化 | `C2-a` 在不减少必要覆盖的前提下，实时检查位姿、距离、角度、耦合、速度、覆盖和信号质量，不合格就当场重扫；`C2-b` 在基本覆盖完成后，把低置信度或异常边界不清区域变成补扫指令；`C2-c` 才讨论用粗扫决定非均匀采样。三层不得混成一个承诺 |
| 已有部分 | 位置编码扫查、相控阵、全聚焦、曲面扫描和 AI 判伤分别存在；Evident FlexoFORM 等已经覆盖曲面适应、编码扫查和二维数据图。`F-P·内部材料／杨观察`：方强团队有相关超声、热成像硬件和软件 Demo 线索；实时闭环集成和工厂重复验证仍为 `Ø` |
| 计算角色 | C2-a：位姿拼接、覆盖和采集质量判断；C2-b：不确定性地图和补扫规划；C2-c：自适应采样。最终缺陷判定仍由合格人员承担 |
| 我方可能控制 | 探头接口、跟踪结构、扫查协议、补扫逻辑、证据链与特定曲面工艺数据 |
| 新增／牺牲 | 新增跟踪、耦合监测、实时计算、校准、验证和检测责任；C2-c 可能漏过模型未见异常，因此模型低不确定性不能代替物理覆盖 |
| 最大未知 | C2-a 能否先减少无效数据、重复扫查和返场；C2-b 是否改善证据完整性；行业是否允许 C2-c 非均匀采样，以及如何证明没有漏掉承重缺陷 |
| 可推翻条件 | 若 C2-a 不能改善覆盖、无效数据或操作者重复性，则先停止共研；若 C2-b 不能在相同漏检边界下降低重复扫查／返场，则不继续；合规仍要求固定全覆盖时，不启动 C2-c |
| 依赖层级 | `C2-a：H·中期跟踪／耦合监测＋经典控制`；`C2-b：H·中长期算法＋验证`；`C2-c：H·长期行业验证`。方舟只提供内部原型线索，不提高商业证据等级 |

## 六、路线 D：可控激励与计算感知

### D1｜维修人员的可编程声学／振动诊断探头

> 处置：`关闭 LT-01 当前版本`。“一机多用”本身不足以证明任务能力或硬件架构改变；多种接收器、发生器、空气／接触探头和听诊附件的低价组合只有前序 Agent 快查线索，本轮未保存可耐久原始链接，不作为单独关闭证据。若未来按普通 B 线产品重新研究，须重开商品原页。以下原构思保留用于解释关闭原因。

| 字段 | 当前构思 |

## 七、方舟技术共研接口（不计产品构思数）

### T1｜复杂曲面采集质量闭环

`H·共研技术假设`：在不减少合规覆盖要求的前提下，利用位姿、距离、角度、耦合和信号质量监测，减少无效数据、重复扫查和事后返场。首个对照应限定为一种材料、一个曲面试件、一类已知缺陷和一种主要传感方式，比较人工／固定网格基线、方舟当前系统和增加质量闭环后的系统。

T1 不计方向 B 新产品构思，不代表已决定合作。若不能访问设备、原始数据和日志，或对照实验不能改善覆盖、无效数据或重复性，则停止当前共研判断。

### T2｜主动激励与下一次测量选择

`H·长期共研技术假设`：根据当前响应改变激励频率、能量、位置、方向或传感模态，以取得原本没有被充分观察的物理信息。T2 比 T1 验证负担更重，不与 T1 同时启动，也不在没有稳定基线时直接使用复杂模型。

## 九、最强反例与共同停止线

1. **Shaper 反例**：局部闭环没有消除工业化；定位耗材、逐台标定、执行器和上游主轴仍承重。
2. **Light／Lytro 反例**：新能力和巨额融资不自动产生购买理由；退出原因仍为 `Ø`，不得简化为算法失败。
3. **低场 MRI／Tesla 反例**：删除物理性能或独立传感模态后，算法不能保证恢复未观测信息；必须有任务边界、补采或安全退化。
4. **Butterfly／通用器件反例**：合并专用硬件可能增加芯片、库存和生命周期风险，一机多用不等于净成本更低。
5. **方舟整合幻觉反例**：硬件照片、UI 和算法结果同时存在，不证明扫描、激励、重建和判读已经在同一系统中实时闭环；看样机时必须逐段确认。

八个构思共同停止于构思孵化。任何对象进入商业深挖前，必须先回答：

1. 本轮具体看哪个产品或用户任务？
2. 什么真实行为说明它被选择过，或为什么原创任务值得直接验证？
3. 哪条信息会改变产品判断？
4. 完成后距离我方方案或真实交易验证近了哪一步？

## 一句话定位

从全球已经卖得好、增长快或获得大量付款支持的具体产品出发，理解用户为什么买，创造我方可控制、用户可感知的产品或服务差异，并用有上限的真实交易验证它能不能赚钱。

VentureLab 仍是 PB 与 SK 之间的公共研究层，但研究、模板和治理都只是实现上述目标的手段，不是项目进展本身。

## 方向 B 北极星与总战略

方向 B 的北极星不是“找到更多产品资料”，也不是“从 1688 找到热销同款去卖”，而是：

> 以别人已经付过的钱为起点证据，理解受欢迎的原因；再通过改良、优化、组合、迁移或重新定义，形成市场上没有等价可得方案的我方差异；最后以高投入回报比尽快完成真实交易验证。

默认顺序：

1. 从全球与中国已验证畅销、近期增长、众筹成功或持续被用户选择的具体产品进入；
2. 杨先观察和理解用户为什么买、为什么买它、为什么现在买；
3. 再围绕入选产品定向整理差评、退货、问答、土办法和现有替代，不从随机抱怨反向发明需求；
4. 形成更便宜、更方便、更好用、更清楚或更合适的方案，也重点寻找把现有机制迁移给原本不用的人、原本不用的场景或尚未被满足的任务；
5. 中国通常作为低成本首验市场，但不排除面向具体海外国家、渠道和人群；
6. 通过发现门、创造门和行动门后，才交给 TradeLab 做封顶交易实验。

榜单、第三方报告、文章、博主、UP 主、测评视频、创业节目和众筹平台共同构成可持续更新的**产品发现入口**。它们负责扩大视野和提供线索；入选后必须回到具体 SKU、原始页面和用户行为核验。深度研究只用于已经锁定的产品和会改变取舍的关键未知，不是发现产品的默认起手式。

## 项目第 0 步

启动新方向、新项目、新候选池，或重大改变现有目标前，先完成 [`meta/项目第0步-主体与任务声明.md`](meta/项目第0步-主体与任务声明.md)：明确“我是谁、我要为谁做什么、本阶段只验证什么、什么情况下停止”。主体和任务未对齐时，不用扩大搜索来代替澄清。

方向 B 当前服务对象暂定为“判断型小产品经营者”，完整画像见 [`meta/B线目标使用者画像.md`](meta/B线目标使用者画像.md)。该画像当前为 `H·待外部验证`，不能因为内部描述合理就升级为市场需求事实。

## 产品记忆库

`products/` 是仓库面向人和未来检索系统的规范产品记忆层。一个已确认的产品只建立一个目录和一张 `product.md`；杨的原始观察、平台采集、案例卡、研究报告和证据文件保留原位，由产品卡用链接聚合，不复制成第二份事实。

- 总索引：[`products/INDEX.md`](products/INDEX.md)
- 维护规则：[`products/README.md`](products/README.md)
- 字段结构：[`products/SCHEMA.md`](products/SCHEMA.md)
- 迁移顺序：[`products/迁移与维护计划.md`](products/迁移与维护计划.md)

新窗口、Claude 与 Cursor 遇到具体产品时，先查总索引：已有对象更新原卡，新对象确认主体后再分配稳定编号。原始 `inbox/` 和 Agent 报告不直接作为默认 RAG 语料；规范产品卡才是默认召回入口。进入产品记忆库只代表“值得被记住和复用”，不等于进入案例库、假设账本、项目第 0 步或 TradeLab。

## 旁路证据沉淀与候选治理流程

当前机会决策主漏斗以 `机会发现期执行计划.md` 为准。以下流程描述外部材料如何长期入库，不替代当前阶段的机会发现顺序：

1. 外部发现先进入 `inbox/`；
2. 核清主体、产品、服务、时间和来源；
3. 已确认的具体产品先查 `products/INDEX.md`：已有对象更新原目录，新对象按一产品一目录沉淀；失败、停运或并入状态同时按需链接 `tombstones/`；
4. 高负重结论进入 `evidence/` 做来源审计；
5. 跨样本规律进入 `patterns/`；
6. 旁路材料不能仅凭样本完整、模式新颖或 Agent 共识升级为创业候选；
7. 候选满足当前阶段执行文件的进入条件后，才进入 `opportunities/`；
8. Codex 与 Claude 先密封式独立研究；
9. 交换报告后先做证据归一，相同来源只计一次；
10. 双方在 `research/cross-review/` 对称质询对方和自己；
11. 联合输出保留共识、相关性共识、未决分歧和双方各自建议；
12. 杨确认后，成熟结论才可向 PB 或 SK 交接。

## 证据规则

统一使用：

- `F-M`：真实市场行为；
- `F-P`：公司、项目或仓库内部事实；
- `I`：合理推断；
- `H`：待验假设；
- `Ø`：无材料。

只有 `F-M` 能对商业排序产生强加分。官网客户案例、投资方材料和媒体报道均需保留来源属性与利益关系。

## Claude × Codex 协作边界

```text
问题对齐
  → Claude / Codex 密封式独立判断
  → 交换报告并归一证据
  → 双方对称质询对方和自己
  → 保留共识、共同盲区和未决分歧
  → 给杨一张通俗决策卡
  → 杨确认后由 Codex 写盘或继续取证
```

- Claude 可以直接读取 `D:\VentureLab`，无需重复上传核心文件；
- Claude 不创建、修改、删除、移动或归档本地文件，不执行会改变仓库状态的 Git 操作；
- Claude 引用本地材料时必须给出完整路径和定位信息，并注明读取快照时间；
- Codex 负责评估 Claude 工单、核验高负重结论、处理文件写入与 Git；
- Claude 与 Codex 的原始报告必须分账保存，联合结论另存 `research/cross-review/`；
- Agent 报告本身不是事实源，进入产品卡、墓碑卡或机会候选前必须回到原始来源。
- Claude 可以参与研究决策、质询 Codex，并提出自己的系统指令修订工单，但不能直接写盘或扩大自身权限；
- Codex 不因负责写盘而自动成为判断裁判；双方的研究建议必须分别保留；
- 两边引用同一来源不构成双重验证，多家媒体转载同一稿件仍按一个来源处理；
- 每个重大阶段先给杨“90秒版本”：做什么、为什么、新证据、未知、分歧、下一步和是否需要决定；
- 完整协作规则见 `双AI联合讨论与决策协议.md`。

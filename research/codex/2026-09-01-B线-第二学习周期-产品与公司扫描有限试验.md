## 三、本轮要决定与不决定什么

### 要决定

1. 跨平台产品扫描能否继续提高杨的产品判断和迁移能力；
2. 分维度记录能否更早淘汰弱产品或暴露关键 `Ø`；
3. 公司强弱产品对照能否产生可检验预测，而不仅是事后解释；
4. 第二周期结束时，是否出现一个值得进入项目第 0 步的具体对象。

### 不决定

- 不证明创新智能 AI 仓库已经成为产品；
- 不建立正式创新 SOP、Skill 或新方法目录；
- 不把任何新产品自动写入正式 C 案例、B-H 假设或 TradeLab；
- 不授权联系真人、询价、拿样、下单、发布、报价、预售或收款；
- 不保证本周期一定找到可赚钱产品。

## 五、产品段：Amazon 美国站 5 个精确 SKU

### 5.1 发现边界

- 以 Amazon 美国站作为主要零售发现入口；官方品牌页、说明书、其他零售页和可核评论只用于交叉核对。
- 必须锁定品牌、产品名、型号／料号、商品页和采样日期；系列名不能代替精确 SKU。
- Amazon Best Sellers、Movers & Shakers、评论数、星级、`bought in past month` 等均属于平台显示口径，不能单独证明审计销量、利润或购买原因。
- 一批可以一次发现 5 个名称，但教学顺序仍为“一次一个、杨先开口”。

### 5.2 样本结构

首批尽量覆盖五种不同观察价值，避免再次全是同一种实用产品：

1. 高频动作／流程微改良；
2. 材料或结构替代；
3. 专业能力消费品化；
4. 情绪、礼物或体验型产品；
5. 被明显选择但差评暴露强 trade-off 的反例。

样本结构只是发现约束，不等于产品类别配额；找不到合格精确 SKU 时保留 `Ø`，不为凑数降低证据标准。

### 5.3 单产品学习顺序

1. Agent 只提供产品名、精确 SKU、原始商品页和必要演示；
2. 杨先回答：谁用／谁付、想得到什么、旧方案、真正改变、牺牲与新增麻烦、回退意愿、第一眼失败猜测；
3. Agent 再补官方事实、平台显示、强替代、差评、退货／长期结果线索与 SKU 冲突；
4. 对照杨的事前判断：支持、削弱、推翻或 `Ø`；
5. 只有已经看到具体未解决部分时，才最多形成 1 条“我方会改的是 X”的 `H`，并写用户、场景、旧替代、新增不便和推翻条件；不得为完成指标强造创新；
6. 若尚缺一条会改变判断的信息，允许提出一次有边界的定向补充，写明问题、人工时间与停止点；补完后不得继续追加问题；
7. 杨分别裁决学习状态与机会出口：学习状态可为已理解、部分理解、暂停或跳过；机会出口只能是“我方会改的是 X”或“没有可改的，关闭”。机制参考可以保留，但机会侧按关闭处理。

### 5.4 灵感入口、复制边界与机会出口

- 即时灵感默认只逐字记录，并翻译为“应去看哪类货架／哪些精确 SKU”，不直接展开结构、功能、目标人群或商业模式。
- 找到第一个可观察的精确 SKU 后，停止自由方案推演，先完成主体、交易、当前替代、承重机制和未解决部分的观察。
- “复制”只指合法复现或取得市场已经证明承重的用户结果、产品机制、供应基准或交易基线；不授权仿冒、侵犯知识产权、规避监管或把原样现货成交冒充自有创新。
- 创新只作用于已观察到的未解决部分；不得先保留旧构思部件，再为部件更换用户任务。
- 特殊情况不由 Agent 从“新颖”“杨喜欢”或“暂时没找到同类”推定，必须由杨明确授权，并记录为何偏离 SKU 起点、适用范围与回到主线的条件。
- Amazon 5 个 SKU 若都没有形成“我方会改的是 X”，产品段到此停止；复盘时选择换货架、修订入口或停止，不自动看第 6 个。

## 六、公司段：Misen 2 强＋1 弱对照

公司段沿用 [`Misen 产品逆向工程矩阵 v0.1`](2026-08-28-Misen产品逆向工程矩阵-草案.md)，不新建 `companies/` 目录或第二套公司状态机。

第一轮优先选择能够形成时间关系的 3 个对象：

- Pre-Seasoned Carbon Steel：相对强项目候选；
- Modular Knife Storage：相对弱项目候选；
- Carbon Nonstick：相对强项目候选。

“强／弱”只表示当前公开平台结果的相对线索，不能自动写成利润、长期经营或产品质量结论。

固定检查：

1. 公司反复选择哪类成熟任务、旧规则或用户负担；
2. 产品拉力、品牌／老客拉力、页面转化与交付能力如何分账；
3. 上一代反馈是否有原始材料证明进入下一代；
4. 强项目解释能否解释弱项目，而不是只保护成功叙事；
5. 事前写下对下一产品命题、代价转移和复用资产的预测，再打开后续结果；
6. 公开材料最多支持“可观察创新结构”，不得冒充 Misen 内部真实 SOP。

## 七、分维度评价卡

每个维度允许使用 `0—3／Ø` 或 `强／中／弱／Ø`，但必须附证据标签和一句理由。不同维度禁止求和、加权或形成综合排名。

### 7.1 用户与真实选择

| 维度 | 要回答什么 |
| --- | --- |
| 真实选择 | 付款、在售、复购、评论、交付分别有什么证据；来源是否独立 |
| 交易角色 | 谁使用、谁决定、谁付款，预算从哪里来 |
| 用户任务 | 想取得什么结果；频率、严重度和失败代价 |
| 当前替代 | 用户现在怎样完成；零成本方案、土办法和不处理分别是什么 |
| 未解决缺口 | 当前方案具体哪里仍不够；是否有买家亲口证据 |
| 回退不适 | 换回旧方案失去什么；属于产品拉力还是制度锁定 |
| 拉力分账 | 产品、品牌、内容、平台、价格与渠道分别承担什么 |

### 7.2 创新与差异

| 维度 | 要回答什么 |
| --- | --- |
| 创新类型 | 删除、强化、迁移、组合、材料／结构替代或新原理；只分类，不自动加分 |
| 差异可感知 | 购买前可见，还是使用后才知道；能否清楚演示 |
| trade-off | 解决什么，同时牺牲什么、新增什么麻烦 |
| 等价可得性 | 相同用户、场景、价格、渠道和信任条件下是否已有等价方案 |
| 我方控制 | 规格、设计、模具、流程、品牌、内容、客户关系或服务标准 |
| 成功后留存 | 供应关系、内容资产、客户、复购、服务组件或 `Ø` |

### 7.3 制作、交付与责任

| 维度 | 要回答什么 |
| --- | --- |
| 技术成熟度 | 原理是否成熟；关键性能是否可测 |
| 原型与制造 | 原型难度、供应链、MOQ、良率、模具和单一供方依赖 |
| 质量与售后 | 耐久、误用、退货、维修和耗材责任 |
| 合规与权利 | 认证、知识产权、隐私、安全和产品责任 |
| 履约 | 包装、物流、税费、本地化和交付周期 |

### 7.4 赚钱与验证

| 维度 | 要回答什么 |
| --- | --- |
| 单位经济 | 售价、成本、运费、平台费、退款损失分别记录；只计算同单位比值 |
| 市场进入 | 具体国家、渠道、触达、信任和杨的可进入性 |
| 可证伪性 | 下一条最便宜关键信息、现金、人工时间、自然周期和样本 |
| 外部动作 | 询问、拿样、报价、预售或交易测试中，哪一个能判错 |

### 7.5 决策方式

采用“关键项否决＋并排比较”，不采用总分最高者胜出。

以下任一关键项为 `Ø` 时，不得用其他高评价抵消：

- 是否存在真实选择行为；
- 是否说清未解决缺口；
- 是否存在我方可控制、用户可感知的差异；
- 是否有可执行的推翻路径。

评价卡是杨的决策辅助，不自动通过发现门、创造门、行动门或晋级 TradeLab。

## 八、方法与记忆沉淀

本试验允许自然产生方法观察，但不以建立方法论为本轮产出指标。

- 原始观察继续进入 `inbox/杨观察与灵感/`；
- 已确认产品按 `products/` 现行准入和去重规则处理，不批量灌库；
- 迁移灵感只记 `H`，不得混为已售产品或正式方案；
- 新观察至少在 3 个独立产品中重复并有 1 个反例，才讨论模式成熟度；
- 同一流程至少独立运行 2 次，且至少一次减少漏项／返工或改变取舍，才讨论正式 SOP／Skill；
- 方法记录时间若超过产品理解和证据核验时间，立即停止扩充方法字段。

## 九、成功、失败与无结论

### 成功条件

本试验至少满足以下 3 项，才值得讨论固化：

1. 后续证据至少一次明显修正杨的第一判断；
2. 至少一条迁移灵感同时召回强等价替代或反例；
3. 分维度评价实际淘汰、降级或提升一个对象；
4. Misen 公司段形成一个可检验预测，而不是只解释历史；
5. 至少出现一个值得讨论是否进入项目第 0 步的具体对象。

### 停止线

- Amazon 5 个产品完成即停，不自动扩第二批；
- 每个深入观察的 SKU 必须完成机会出口；“已理解”但未写“改 X／关闭”视为未完成，不得以新报告替代裁决；
- 连续 3 个产品只产生漂亮解释、没有改变取舍，停止当前扫描问题；
- 新增迁移灵感超过 3 个，却没有一个说清用户、缺口、等价替代和推翻路径，暂停生成；
- Amazon 5 个产品均无“改 X”时，不扩第 6 个，产品段复盘优先裁决是否换货架；
- Misen 前两个重点产品仍只能总结“页面好、筹款多、品牌强”，停止公司段；
- 第二周期结束仍没有一个对象值得进入项目第 0 步，必须复盘学习为何没有转化，不默认切换第三个平台；
- 任一阶段发现需要询价、拿样、发布、报价、收款或支出，停在授权门前等待杨决定。

### 无结论处理

关键页面不可访问、SKU 无法锁定、评论与销量口径冲突或公司弱项目缺材料时，保留 `Ø` 并停止相应外推；无结论不算失败，也不允许用更多推断补齐。

## 十、偏差检查

- **幸存者偏差**：产品批次必须保留 trade-off 反例；公司段必须有弱项目。
- **新奇偏差**：创新类型不自动加分，先问真实任务和替代。
- **平台偏差**：Amazon 的评论、排名和推荐机制不能外推为全球市场。
- **公司叙事偏差**：公开页面只能支持可观察结构，不能证明内部 SOP。
- **规模幻觉**：评论数、sold、GMV、筹款额不等于利润或普通经营者可进入。
- **确认偏差**：每个迁移灵感必须同时查强等价替代和推翻条件。
- **研究拖延**：达到批次上限必须复盘，不以“再看几个”自动续期。

我为什么可能错：第二批产品可能确实快速产生可验证对象，而本试验的停止线过于保守；也可能当前真正需要的不是更多产品，而是让 TutorAI 或倒计时礼物笔尽快接受外部行为判错。

## 十一、到期与回退

复盘触发：完成 Amazon 5 产品＋Misen 公司段，或提前触发任一停止线。

到期后只有四种裁决：

1. 停止当前扫描方式；
2. 修改观察问题后再运行一次 L1 试验；
3. 选择一个具体对象进入项目第 0 步；
4. 证据满足时，另行论证是否把有效部分固化为正式 SOP。

未复盘时，本试验不得静默永久化；自动回到“待论证输入”。

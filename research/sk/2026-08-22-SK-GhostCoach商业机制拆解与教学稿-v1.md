## 一、杨的 90 秒版本

**GhostCoach 根本不回答"普通人该做什么生意"这个问题。** 它把用户范围收窄到几乎极限：**已经或正在做单人订阅软件的创始人**——尤其是用 Cursor、Lovable、Bolt 之类工具把产品做出来了，却卡在定价、获客、激活、流失和收入上的那批人。`F-P`

核心流程：

```
用户描述产品、阶段、瓶颈和数字
  → 系统先问一个会改变建议的问题
  → 把问题归入五个固定支柱之一
  → 只给一个明确建议
  → 以一个本周动作或一个关键追问结束
  → 保存产品、阶段、瓶颈、90 天目标与会话上下文
  → 高价层每周主动发 3 个动作、季度做一次定价审计
```

**那一刀：它的产品选择不是"模型更聪明"，而是三件事——极窄对象、固定诊断框架、每次只给一个动作。** `F-P`

**第二刀，也是这个样本最特别的地方：厂商自己公开写明底层用 Anthropic API，并且亲手发布了一篇"如何把 Claude 配成商业教练"的指南。** `F-P`

**它等于自己把替代方案摆在官网上。**

这件事必须双向理解，不能只取一边：

- 它**可能**是诚实的边界声明——把话说清楚，筛掉会退款的人；
- 它**也可能**是 SEO／获客内容——用"vs Claude"这类比较页吃搜索流量，同时把自己塑造成敢说实话的那个。
- **真实用户替代行为：`Ø`。** 不能从"厂商公开承认"推出"用户会替代"，也不能推出"这层没价值"。

价格：Builder 79 美元／月、Operator 99 美元／月、14 天试用、另有 499 美元终身方案（称限前 50 名）。**全部是挂牌价 `F-P`，不是成交。** 官网列出三名匿名 early users 及收入／流失改善——**厂商策展证言，不记独立 `F-M`。**

政策页面仍出现 `[Founder name]`、法律实体、注册号、地址、支持邮箱等占位符。`F-P`
**这说明运营成熟度存在风险，不能推出无客户、必然不合规或产品无效。**

**对 EarnPath 最值得带走的一句：不要用一个框架服务所有赚钱路线；先限定一种商业模型，再用一个能改变结论的变量去诊断。**

**但它没有回答的那个问题，恰好是它自己提出来的：用户为什么不直接用 Claude？** `H`

## 二、它服务哪个用户阶段

三个阶段必须分开：

```
① 尚未决定做什么
② 已有项目、准备验证
③ 已经经营、卡在具体数字
```

**GhostCoach 主要处于第 ③ 阶段。** 厂商定位是 `F-P`，**真实客户构成 `Ø`。**

**明确服务**（`F-P·厂商定位`）：单人创始人；订阅软件、SaaS、App 或其他经常性收入产品；pre-launch、刚上线或增长停滞阶段；**已有具体问题和数字**、希望拿到一个建议的人。

**明确不服务**（`F-P`）：需要融资、人脉、介绍或团队管理的人；服务业、电商、实体商品和一次性软件；需要法律、税务、财务、HR 专业意见的人；**主要缺动力和社会压力、而不是缺策略的人**；已进入更大组织和高复杂度阶段的公司。

**这份"不服务"清单比"服务"清单更有教学价值。** 一个产品敢明确写出五类拒绝对象，说明它已经想清楚自己的诊断框架在哪里会失效。**大多数产品不敢写，因为写了就等于承认市场变小。**

**它的典型购买触发**（`F-P`）不是"我想赚钱"，而是：

- 产品上线了，有注册但没人付钱；
- Product Hunt 来了一波流量，却没有持续获客；
- MRR 停滞，不知道是获客问题还是流失问题；
- 定价不敢提高；
- 用户在流失，但不知道流失发生在生命周期哪一段；
- 用 AI 做出了产品，却没把它变成生意。

**判断（`I`）：这是一组高可核卡点。** 用户至少能提供价格、注册数、MRR、流失时间窗、渠道等数字；建议也能较快被后续结果证伪。**它比"选择人生赚钱路线"更窄、更高频、更容易形成持续上下文。**

## 三、它真正卖什么

**不要写成"AI 商业教练"。** 那四个字把它的全部产品选择都盖住了。拆开是七件事：

1. **固定的 SaaS 经营框架**（Ghost OS 五支柱）；
2. **结构化业务画像**（产品、阶段、瓶颈、90 天目标）；
3. **先诊断，再建议**；
4. **每次只追问一个会改变结论的变量**；
5. **每次只给一个动作**；
6. **保存阶段、瓶颈、目标和经营状态**；
7. **会后邮件、周报与季度复检**。

**这七件事合起来指向一个判断（`I`）：它卖的可能不是更多知识，而是"把 Claude 配置好、维护好、并且约束住"这件事本身。**

三个动词都要分开看：

- **配置**——用户不必自己写系统提示词、不必设计框架；
- **维护**——状态会被保存和更新，用户不必每次重新交代背景；
- **约束**——这一条最容易被忽略：**它强制模型只给一个建议、只问一个问题、只在五个支柱里回答。** 通用模型的默认行为恰恰相反——它倾向于给你八条建议、每条都合理、你一条也执行不了。

**但立刻钉死：真实付款理由 `Ø`。** 上面整段是产品结构推断，不是用户为什么掏钱的证据。

**方案与价格**（全部为挂牌 `F-P`，成交、使用频率、续费均 `Ø`）：

| 方案 | 挂牌价 | 主要交付 | 边界 |
|---|---|---|---|
| Builder | 79 美元／月 | 无限会话、业务画像、会话上下文、90 天目标、会后邮件 | 成交与续费 `Ø` |
| Operator | 99 美元／月 | Builder 全部 ＋ 周一 3 个动作 ＋ 季度定价审计 | **"Most popular" 是销售标签，不是销量证据** |
| Lifetime | 499 美元一次性 | 终身 Operator 权限，称限前 50 名 | **已售名额 `Ø`**；30 天退款承诺可见 |
| 试用 | 14 天 | 降低进入风险 | 试用到付费转化 `Ø` |

它用真人教练 200—500 美元／次、月度顾问、mastermind 作为价格锚。
**这些锚定价格主要来自它自家的比较内容，不能当作独立市场统计。**

## 四、Ghost OS 五支柱

五个支柱（`F-P·公司方法页`）：

1. **Offer Architecture**——卖什么、卖给谁、如何定价与包装；
2. **AI Delivery Stack**——如何用 AI 交付，而不让创始人自己成为瓶颈；
3. **Acquisition System**——可重复、可拥有的获客渠道；
4. **Automation Layer**——计费、试用跟进、流失预警、入门流程；
5. **Revenue Protection**——转化、流失、扩单与收入保留。

**关键在于它不把五个支柱一次性讲给用户。** 产品先判断当前瓶颈落在哪一支柱，再追问一个能改变建议的变量。

**官网给的例子最能说明这套机制**：用户说"月流失 8%"，系统不直接给降流失方案，而是先问——**流失发生在前 14 天、2—8 周，还是 2 个月之后？** 三个时间窗对应三类完全不同的问题（入门失败／价值未兑现／竞品或需求消失）。`F-P`

**这个顺序在逻辑上为什么可能有意义（`I`）：**
支柱 1 定义"卖什么给谁"，是所有下游判断的前提；支柱 2 决定交付是否可扩展；支柱 3 才谈获客；支柱 4 把重复动作自动化；支柱 5 处理已有收入的保留。**大致是"先确定产品定义，再谈规模，最后谈保住"。** 逻辑顺序合理，**但这只是结构上说得通，不是有效性证据。**

**必须钉死的三条：**

1. **这是厂商公开的方法结构 `F-P`。** 它证明的是"他们这样组织内容"，不是"这样组织更正确"。
2. **不能据此证明建议正确或结果改善。** 建议正确率、执行率、指标改善 —— 全部 `Ø`。
3. **五支柱的内容大量已经公开在它自己的 SEO 页面上。** 也就是说：**它最核心的方法论，是它自己免费发出去的。** 这直接导致下一节的问题。

**可以直接带走的诊断原则（这是全稿最可迁移的一条）：**

> **用户自述的问题不等于真实问题。先找那个能改变建议的分叉变量。**

## 五、"每次一个关键问题、一个动作"为什么可能有价值

**它可能减少四件事**（`I`，均无效果证据）：

- **选择过载**——十条建议摆在面前，用户什么都不做；
- **反复换题**——今天问定价、明天问获客，没有一条被推进到底；
- **一次给太多建议**——通用模型的默认失败模式；
- **只读不做**——读完觉得很有道理，然后关掉。

**机制上说得通的理由（`I`）：** 一个动作可以被验收，十条建议不能。下一次会话可以从"上次那个动作做了没有、结果如何"开始，**这本身就制造了回访理由**——而回访是订阅制的命脉。

**但四条边界必须同时立住：**

1. **用户是否真的执行了 —— `Ø`。**
2. **单一建议是否比多条建议更正确 —— `Ø`。**
3. **是否改善了经营数字 —— `Ø`。**
4. **最重要的一条：更果断 ≠ 更准确。**

第 4 条要展开讲，因为它是这套设计的自带风险：**决断质量完全依赖输入的数字质量和诊断质量。如果诊断错了，"只给一个动作"意味着错误建议被以最不容置疑的方式交付出去——而且因为只有一条，用户没有对照，更难发现它是错的。**

**给多个选项的产品，把判断责任留给用户；只给一个动作的产品，把判断责任接了过来。** 接过来就要能承担——**而它同时明确写着不对高风险专业建议负责。** 这两件事之间存在张力，公开材料没有解决它。

## 六、价格、获客与商业发动机

三层必须分开写。

**① 可见获客入口** `F-P`

- 围绕 SaaS 定价、流失、获客和 vibe coding 的**大量 SEO 指南**；
- "GhostCoach vs Claude／MentorCruise" 等比较页；
- 免费 14 天试用；
- 每周邮件；
- 匿名早期用户案例；
- 用明确、强观点的短句建立"教练人格"。

⚠️ **不要把 SEO 页面数量当成分发成功。** 页面多只能证明**内容产出多**，不能证明有流量、有转化、有付费。**没有排名数据、没有流量数据、没有归因——`Ø`。**

**未找到**足以承担结论的 Product Hunt 当前发布、独立评测、实名客户、公开社群、合作渠道或付费流量证据。`Ø`
**注意措辞：`Ø` 是"公开检索到此为止"，不是"不存在"的负向断言。**

**② 价格与方案** `F-P`
79／99／499 与 14 天试用，见上一节。**全是挂牌。**

**③ founding cohort 与匿名证言** `F-P·厂商策展`

- 三名匿名 early users；
- 其中一人被描述为**6 周做到 1,800 美元 MRR**；
- 一人被描述为**流失从 28% 降到 11%**；
- 团队称有 founding cohort，并称每周使用的人得到的建议更好。

**这四条全部不能升级。** 不能核验的是：用户真实身份与产品、是否付款、结果是否由 GhostCoach 导致、退款与续费、使用频率、50 个终身名额是否售出、框架建议错误率、建议真实执行率。

**"每周使用者建议更好"这一条尤其要拦**：即使为真，也可能是选择效应——**认真经营的人本来就更愿意每周用，也本来就更容易做出结果。** 因果方向未定。

**④ 真正的发动机** `Ø`
真实付款、续费、流失、退款、获客成本、试用转化——**全部空白。**

**因此本节结论只能写成：**

```
产品、框架、价格和销售内容存在        → F-P
商业发动机、付款、留存和结果           → Ø
```

## 七、与 Claude Project 的替代关系（全稿核心）

**这一节是 GhostCoach 独有的价值。其他样本都没有把自己的替代方案写在官网上。**

**Claude Project 可以近似什么**（`F-P`，出自厂商自己发布的指南）：
在 Project 中维护产品描述、当前阶段、当前瓶颈、90 天目标；要求先诊断再建议；要求每次只给一个建议。

**GhostCoach 声称自己多提供什么**（`F-P·厂商自述`）：

- 已写好的 SaaS 框架；
- 结构化业务画像；
- 自动维护上下文；
- 会后邮件与周报；
- 用户不需要自己设计系统。

**哪些差异只是省配置时间（`I`）：**
已写好的框架、不必自己设计系统、初次搭建的一小时——**这些是一次性成本，配好之后就不再发生。** 一个愿意花一小时的人，可以把这部分差距抹掉大半。

**哪些差异可能形成持续价值（`I/H`）：**

- **自动维护上下文**——不是"能存"，而是**用户不必自己记得去更新**。手工 Project 的状态会腐坏：三个月后里面写的还是三个月前的瓶颈。
- **会后邮件、周报、季度审计**——**产品能主动开口**。手工 Project 永远等你先说话。
- **约束力**——它强制单一建议；手工配置里，用户随时可以说"再多给几条"，然后模型就给了。

**这三条的共同点：它们对抗的不是能力差距，是用户的惰性和自我放松。**

**哪些差异尚未经过同题实测（`Ø`）：**
**全部。** 没有冻结输入、冻结版本的多轮基线比较。所谓"Ghost OS 比认真配置的 Claude 更正确"——**没有任何证据，`Ø`。**

**因此准确状态只有三行：**

```
替代路径公开存在              → F-P
增量效果、替代率和付费价值      → Ø
容易被认真配置的通用模型近似    → I（推断，未做基线实测）
```

**不能写 GhostCoach 优于 Claude。不能写 Claude 可以完全替代 GhostCoach。**

**它自己提出的那个问题，就是它的全部商业风险：**

> 用户是否愿意每月付 79—99 美元，买"替我把 Claude 配置、维护和约束好"，而不是自己花一小时建一个 Project？`H`

**当前没有任何付款与留存数据回答这个问题。**

## 八、AI 能做什么，不能做什么

**AI／软件承担**（`F-P`）：追问和诊断；把问题映射到五个支柱；输出一个建议和可用模板／SOP；保存结构化状态；触发会后邮件、周报和季度审计。

**人类经验的角色**：厂商声称 Ghost OS 编码了 SaaS 创始人、运营者与顾问的多年经验，**但没有公开方法语料、贡献者名单、案例分母或验证流程。** `F-P/Ø`
**"编码了经验"目前是一句主张，不是一项资产。**

**产品主动承认不能做**（`F-P·厂商边界陈述`）：

- 不提供客户、投资人或招聘介绍；
- 不形成真正的人际关系与社会压力；
- 读不出用户没有说出的现场气氛和回避；
- 不为用户背书；
- 不替用户执行；
- 不对高风险专业建议负责。

**这份清单值得单独记住，理由有两层：**

第一层：**它比"AI 教练能替代真人"更可信。** 一个愿意公开写出自己做不到什么的产品，在信息上更值得采信。

第二层（更重要）：**这六条恰好是真人教练收 200—500 美元／次的真正原因。** 人脉、社会压力、读场、背书、代执行、承担责任——**AI 拿走了"给建议"这一段，把这六段全留给了人。** 这解释了为什么价格能从 200—500 美元／次掉到 79—99 美元／月，也解释了**为什么这个价格可能已经是这一层的天花板。** `I`

**但仍要标清：这是厂商自述的边界，不是第三方验证。**

## 九、可复制机制 vs 声称但未证明的资产

**可复制的八条机制：**

1. **只服务一种商业模型**（窄对象）；
2. **固定框架**，不临时组织回答；
3. **结构化状态**（产品、阶段、瓶颈、目标）；
4. **先诊断，后建议**；
5. **每次只问一个会改变结论的问题**；
6. **每次只给一个下一步动作**；
7. **周期性复检**（会后邮件、周报、季度审计）；
8. **明确写出 AI 不能做什么**。

**声称但未证明的"资产"（最高只到 `F-P/H/Ø`）：**

- Ghost OS 的独特经验编码 —— `F-P·自述`／有效性 `Ø`；
- 多位成功创始人的模式库 —— 无名单、无分母 `Ø`；
- 随会话增长的专有业务数据 —— `H`；
- 建议—结果配对 —— `Ø`（这是**唯一可能形成真护城河**的一项，但目前完全没有）；
- 早期用户结果与品牌信任 —— 厂商策展 `F-P`／独立验证 `Ø`。

**要害判断（`I`）：框架内容大量已经公开，底模就是 Claude，第一版产品很容易被认真的提示词和项目记忆模仿。真正可能长成资产的是"建议—结果配对"——即哪条建议在什么情形下真的改善了指标。但这一项当前是 `Ø/H`，一条也没有。**

**同时保留反向可能：没发现护城河 ≠ 确定没有护城河。** 未公开的后台数据、留存曲线或用户结构，公开检索看不到。

## 十、对 EarnPath 能证明什么、不能证明什么

### 能支持（`F-P/I`）

1. **窄对象＋窄商业模型，比"服务所有想赚钱的人"更容易形成稳定的问题结构。** 用户的问题会重复出现，框架才能复用。
2. **一次性建议之后，可以用状态和经营数字继续交互。** 价值不在一次性知识，在于把同一框架反复应用到用户自己的数字上。
3. **先问一个会改变建议的问题，可能比直接给路线更有效。**
4. **一个动作比十项建议更容易验收**——而可验收，才有下一次会话的理由。
5. **系统应明确写出自己的边界**，不伪装成人脉、责任和真人压力。

### 不能证明

- 用户**愿意为框架包装付款**；
- **结构化记忆带来续费**；
- **单一决断优于通用模型**；
- 厂商案例**真实且由产品导致**；
- 这套 **SaaS 框架能迁移到实体生意、副业或职业变现**；
- **中国存在同样的付款行为**；
- **EarnPath 应该直接变成一个长期 AI 教练**。

### 最重要的一条反问（阶段错位）

```
EarnPath 假设：用户还在"找／选一个可复制对标"
GhostCoach ：用户已有订阅产品，在诊断经营瓶颈
```

**这不是同一阶段。** GhostCoach 的整套框架**要求用户已经有产品和经营数字**——价格、注册、MRR、流失时间窗。**EarnPath 当前可能服务的人，一个数字都没有。没有数字，"先问一个会改变建议的变量"这个动作根本无从执行。**

**因此结论是（`I`）：如果 EarnPath 把两段同时做，复杂度会相乘；如果只学 GhostCoach，可迁移的是"先诊断关键变量 ＋ 只给一个下一步"这套交互原则，不是它的五支柱内容。**

## 十一、最重要的三个未知

**第 1｜同题基线：冻结输入、冻结版本下，认真配置的 Claude Project 与 GhostCoach 的多轮结果差多少。** `Ø`
→ **这一格决定整个样本的意义。** 差距大 → "把通用模型配置好并约束住"是一门真生意，EarnPath 可以往这个方向走；差距小 → 79 美元／月买的只是省下的那一小时，天花板很低。
**这是唯一一个能被自己动手填上的格子**（用同一份人物卡与同一组问题做对照），且**不需要注册 GhostCoach 账户**——只需在 Claude 一侧建立基线，不违反其条款。**性价比最高的下一步。**

**第 2｜真实付款、试用转化与续费。** `Ø`
→ 它决定"79—99 美元／月的 AI 教练"是不是一个已被验证的价格带。**目前所有价格都是挂牌，一笔可核成交都没有。**

**第 3｜建议—结果配对是否真的在积累。** `Ø/H`
→ 这是它**唯一可能长成护城河**的东西。如果它没在系统性地记录"哪条建议在什么情形下改善了什么指标"，那么它和一份好提示词的差距，会随着通用模型获得记忆和主动能力而持续收窄。

**取数说明：** 第 2、3 格公开检索已到天花板，继续读它的 SEO 内容只会重复同一套主张。真正改变判断的材料只有五类——可核身份的当前或流失付费用户、真实续费／退款／使用频率、同题冻结基线比较、一条建议从提出到指标变化的完整记录、完整法律实体与正式条款更新。**竞争用途测试受其现行条款限制，当前不创建账户。**

## 十二、你最容易记住的三个词，以及每个词何时会骗你

Codex 给的是"专家框架／长期记忆／单一决断"。我保留其中的判断，但**换掉前两个**——按你的关注点（护城河与价值捕获），最容易被你抓走并直接当判据用的，是下面这三个。

| 三个词 | 它会让你以为 | 会使它失效的条件 |
|---|---|---|
| **窄** | 越窄越好，窄就是答案 | **窄降低的是"产品必须理解的商业模型数量"，不自动带来付费意愿。** 窄同时缩小市场和获客池——而 GhostCoach 的**获客证据恰好是 `Ø`**。它证明了窄能让诊断稳定，**没有证明窄能让生意成立**。 |
| **只给一个动作** | 果断就是专业 | **决断质量完全依赖输入数字和诊断质量。错误的建议也会被同样果断地交付，而且因为只有一条，用户没有对照，更难发现错。** 更果断 ≠ 更准确。 |
| **"它自己承认 Claude 能替代"** | 厂商都认了，所以这层没价值 | **公开替代指南同时可能是 SEO／获客／信任筛选内容。** 真实用户替代行为 `Ø`。**不能从"厂商公开承认"推出"用户会替代"，也不能推出"框架无价值"或"价格必然归零"。** 这句话读起来像最高级别的诚实，因此最容易被直接采信——这正是它危险的地方。 |

**提前拦第四个词——"专家框架"：**
会让你以为框架一定比 Claude 强。**框架内容大量已由厂商自己公开，独立正确率和结果 `Ø`，且从未做过同题冻结基线比较。**

**提前拦第五个词——"长期记忆"：**
会让你以为记得越多越值钱。**Claude Projects 可近似"能存"。** 真正的差别在于**状态是否真实、会不会被更新**——手工 Project 的状态会腐坏，而"自动维护"对抗的是用户惰性，不是模型能力。这个区别很细，但它是这一层唯一可能站得住的地方。

**提前拦第六个——"1,800 美元 MRR"和"28% 降到 11%"：**
这两个数字最容易被记成结果证据。**它们是匿名的、厂商策展的、无法核验身份、付款和因果的。既不能升级为 `F-M`，也不能直接判为虚假——正确状态是 `F-P·厂商策展`，代表性 `Ø`。**

## 十三、六个给 KIMI 的复述击穿问题

> 用法：先让杨脱离本稿讲，一次只问一题；讲完后只回四项——**讲对了什么／偷换了哪个概念／丢了哪个成立前提／哪个事实仍是 `Ø`**。不一次给标准答案。不因用词与稿件相同就判定复读，不因用词不同就判错。杨提出稿中没有但合理的新解释，标为新的 `I/H` 并说明需要什么证据，不判错。

**第 1 题｜它为什么不服务"还不知道做什么"的人。**
不看稿，讲清 GhostCoach 服务哪一阶段、明确拒绝哪几类人，以及**它的诊断方法为什么在缺少经营数字的用户身上根本跑不起来**。
*重点检查偷换：厂商定位＝真实客户构成；把"窄"说成"因为窄所以更好卖"。*

**第 2 题｜五支柱与交互顺序。**
说出五个支柱，讲清产品不是一次性讲五支柱、而是怎么用的；用流失那个例子说明"能改变建议的变量"是什么意思。
*重点检查越级：把"顺序在逻辑上说得通"（`I`）说成"这个框架被证明有效"（`Ø`）；忘记框架内容大量已公开。*

**第 3 题｜比认真配置的 Claude Project 多了什么。**
讲清 Claude Project 能近似什么、GhostCoach 声称多什么，并指出**哪几项可能形成持续价值**、理由是什么。
*重点检查：能否说出"它自己把替代方案发在官网上"这件事的双向解释（诚实边界／SEO 获客），而不是只取一边。*

**第 4 题｜哪些差异只是省时间。**
上一题列出的差异里，哪些是一次性配置成本、配完就不再发生？哪些是持续发生的？分界线在哪？
*重点检查丢前提：漏掉"从未做过同题冻结基线比较"——没有这条，任何"谁更强"的判断都不成立。*

**第 5 题｜为什么匿名 MRR／流失改善不能承重。**
"6 周到 1,800 美元 MRR""流失从 28% 降到 11%"分别是什么等级的证据？它们不能证明什么？为什么也不能直接判为虚假？
*重点检查偷换：厂商策展证言＝独立 `F-M`；"每周使用者建议更好"里的因果方向（选择效应）。*

**第 6 题｜EarnPath 该借什么。**
EarnPath 应该借它的交互方法、它的 SaaS 内容，还是都不直接复制？请说出理由，并讲清**两者的阶段错位具体错在哪一步**。
*重点检查：能否指出"用户没有经营数字，则关键变量追问无从执行"这一具体断点，而不是笼统说"阶段不同"。*

**通过标准：** 能解释因果、适用前提、证据边界和失效条件。六题未完成前，不把 GhostCoach 计入"六主体通透"进度。

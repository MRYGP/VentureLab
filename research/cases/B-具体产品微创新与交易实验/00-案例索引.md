# B线案例索引

## 用途与边界

这里保存首批不超过 12 个“具体产品微创新与交易实验”的结构化公开案例。每一例一个 Markdown 文件，命名为 `C01-产品名.md`，从同目录的 `案例模板.md` 复制创建。

本库只记录案例与证据，不授权询价、拿样、联系真人、发布、报价或售卖。案例的交易证据只服务 B 线，不自动成为 EarnPath 的商业证据。

## 机制编号

| 编号 | 当前名称 | 说明 |
| --- | --- | --- |
| M1 | 缺陷 | 修正既有产品中可感知的功能或使用缺陷 |
| M2 | 场景 | 把已有能力带入新的使用时点、动作或环境 |
| M3 | 人群 | 为原本未被充分服务的人群重做产品或交付 |
| M4 | 形态 | 改变外观、结构、组合或表达形态 |
| M5 | 解释或信任 | 改变命名、演示、证据、承诺或理解路径 |
| M6 | 成本结构 | 改变耗材、运输、补充、生产或交付成本结构 |

编号只用于稳定引用，不表示六类已经成为已核规律。`M5` 暂不拆分；若未来证据要求拆分，须保留旧编号映射，不能静默改写历史记录。

## B 线记忆与反馈工作流

```text
原始线索进入 inbox
→ 建立案例卡并通过主体理解关
→ 抄／改良／迁移／不做
→ 正式平移假设登记到 02-假设账本
→ 杨选择活跃假设
→ 固定晋级单进入 TradeLab
→ 实验中
→ 已闭环（支持／证伪／不确定）
→ 结果按原假设编号回流，修正假设与工作机制
```

执行口径：

1. 主体理解关未通过时，只补案例证据，不建立正式平移假设。
2. 案例卡保存“为什么这样归类”；假设账本保存“从案例推出什么、为什么保留或淘汰”。二者不得重复铺陈整份研究。
3. 每个案例作为主来源最多建立 3 条正式平移假设；其他案例可以作为正反参照，但不重复占主来源配额。
4. VentureLab 仓级同时`活跃`的平移假设最多 5 条；`线索`、`已晋级`、`实验中`、`暂停`和已关闭状态不占本仓活跃名额。晋级后改由 TradeLab 的候选、预算、时间与授权门约束；暂停或回流后重新激活前必须重新检查本仓上限。
5. 晋级前必须登记事前预测：目标买家、预期真实行为、通过线、停止线、最强反证和最便宜反证。事后解释不得冒充事前预测。
6. TradeLab 只读取晋级单点名文件。实验结果以假设编号回流；单次成交只能支持该次事前预测，不自动证明机制、B 线或 EarnPath。
7. 新案例先读本索引和 `02-假设账本.md`，再定向读取 2—3 个相关正反案例，不默认全仓扫描。检索可以提出最多 3 条 `H`，但不会自动激活、晋级或占用预算。
8. C01—C11 不重做研究。只允许从已有文件提取明确写过的内容，并加 `[回填 YYYY-MM-DD]`；无法恢复当时依据时保持 `Ø`。C12 和后续案例使用新版模板完整记录。
9. 至少出现 3 个带事前预测的已闭环实验，且同时包含真实付款与明确拒绝或失败后，才复盘是否启用更主动的候选生成；达到门槛不等于自动启用，也不自动增加 TradeLab 预算。

假设编号、状态定义、事前预测和回流字段见 [02-假设账本.md](02-假设账本.md)。

## 录入规则

- 未找到可复核的既有付款或交易线索，不能进入完整案例，只能留在外部候选池。
- `F-M` 必须带来源属性与链接；公司自述和独立证据不得混写。
- 主改良机制只能选一个：M1 缺陷、M2 场景、M3 人群、M4 形态、M5 解释或信任、M6 成本结构。
- 每例只用一个主要角色参与组合统计；成功、被仿、被吸收等次要属性可以另记，但不重复凑配额。
- 必须显式写明基准品证据等级；只有改后产品证据而没有改前基准，不能把因果归给“改了哪一刀”。
- 一例至少有一个反证、限制或未解问题；没有反证不等于案例更强。
- Bug Bite Thing 已完成首轮回源并作为边界案例入库；OMOSHIROI BLOCK 仍是待回源线索，不占首批编号。
- 跨案例工作矩阵见 [01-横向机制矩阵.md](01-横向机制矩阵.md)；它记录 `I/H/Ø`，不是已经成立的方法论。
- 平移假设只在 [02-假设账本.md](02-假设账本.md) 编号和改变状态；案例卡与矩阵只引用编号，不另建平行状态。
- `TradeLab 晋级` 只有杨明确授权并登记来源文件、来源提交号后才能改为“是”；案例入库、研究完成或中国存在供给均不构成自动晋级。

## 3. 状态定义

| 状态 | 含义 | 是否占 5 条并发 |
| --- | --- | --- |
| 线索 | 已通过主体理解关并登记，但尚未被杨选为当前工作假设 | 否 |
| 活跃 | 杨已选择继续补证或准备晋级 | 是 |
| 已晋级 | 已有有效 TradeLab 晋级单，尚未启动实验 | 否，转由 TradeLab 约束 |
| 实验中 | TradeLab 已获得具体实验授权并开始执行 | 否，转由 TradeLab 约束 |
| 暂停 | 保留原记录，等待指定信息或杨恢复 | 否 |
| 关闭·研究反证 | 在进入 TradeLab 前已被证据淘汰 | 否 |
| 已闭环·支持 | 实验结果支持事前预测，但不自动证明完整产品或机制成立 | 否 |
| 已闭环·证伪 | 实验结果达到事前停止线或直接反对核心预测 | 否 |
| 已闭环·不确定 | 实验结束但结果无法区分核心假设 | 否 |
| 作废 | 重复、锚点失效或记录错误；保留原因，不删除编号 | 否 |

`待理解` 属于案例状态，不属于假设状态。主体理解关未通过时不得提前创建正式假设。暂停或已关闭假设重新激活时，必须写明新证据并重新检查并发上限。

## 5. 维护纪律

1. 一条假设只回答一个主要问题、一个主要产品变化；变化了核心产品、买家或付款理由时新建编号，不覆盖旧假设。
2. 每个假设必须指定一个主来源案例；同一案例累计最多 3 条正式假设，关闭后也不释放该案例的累计名额。
3. `线索`不等于活跃候选。AI 检索或报告提出的想法，只有写入本账本并经杨选择后才能转为`活跃`。
4. VentureLab 中处于`活跃`状态的假设不得超过 5 条；新增或恢复前先关闭、暂停或晋级旧项，或取得杨对规则的另行裁决。`已晋级`和`实验中`转由 TradeLab 的候选、预算、时间与授权门约束。
5. 关闭、证伪、作废记录不得删除。必须保留淘汰证据和重新打开条件，防止同一假设换名重来。
6. 回填一律加 `[回填 YYYY-MM-DD]`，只搬运已有明确记录；推断不得伪装成当时判断，无法恢复时写 `Ø`。
7. TradeLab 结果必须按原假设编号回流。单次付款、拒绝或失败只校验登记过的预测，不自动升级为跨案例规律。
8. 机制编号沿用 `00-案例索引.md` 的 M1—M6；编号只是工作分类，不承担因果或商业排序。

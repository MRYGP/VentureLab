## 90 秒版本

本轮讨论形成的最重要变化，不是已经选定了一个新产品，而是把 EarnPath 的候选服务单位从“一个人的整个人生和赚钱路线”缩小为“这个人当前推进的一个具体商业项目”。

由此可以形成三个不同层次，暂时不做二选一：

1. **“个人赚钱路线”可能是入口语言**：用户容易理解，但容易滑向项目推荐、职业规划和泛化咨询；
2. **“个人商业项目加速器”可能是冷启动运营形态**：筛选人和项目，在有限时间与预算内取得第一笔真实付款或停止证据；
3. **“个人商业项目平台”可能是长期形态**：只有结果数据、买方网络、重复交付和交易关系出现后，才有资格成立。

“面向个人商业项目的 YC”目前只适合作为内部机制类比。可借的是筛选、批次、单项目聚焦、固定合伙人、高频反馈、同侪环境和外部里程碑；不能直接借的是股权、幂律回报、品牌、资本、投资人网络和独角兽标准。

杨可以把 EarnPath 本身作为 `Batch 0`，用这套流程验证 EarnPath 能否获得非人情客户和真实付款。这能测试流程和系统上限，不能单独证明普通用户愿意购买，因为杨的资金、AI 使用强度、资源和投入耐心并不典型。

当前最需要防止的升级是：从“YC 类比很有解释力”直接跳到“已经决定做个人 YC”。截至本文形成时，非人情付款、买方网络、私有结果数据、重复交付和单位经济均为 `Ø`。

## 二、三个容易混在一起的概念

### 1. 个人赚钱路线

用户语言可能是：

> 以我的技能、资源、时间和资金，我应该靠什么增加收入？

**可能优点**：入口宽、痛点直观、适合获客和初步诊断。

**可能问题**：

- 服务边界接近整个人生，难以验收；
- 容易变成项目列表、报告、职业规划或成功学；
- 通用模型可以低成本生成候选、风险和计划；
- 用户可能把“路线推荐”理解为结果保证；
- 失败后难以区分路线、执行、市场和个人状态。

### 2. 个人商业项目加速器

候选定义：

> 筛选已经具有部分筹码的人，每次只推进一个具体商业项目，在限定时间、预算和责任边界内，帮助项目取得第一笔真实付款、明确的市场信号，或足以停止的反证。

这里的服务对象不是人的全部，而是一个具有以下字段的项目：

- 明确付款者；
- 具体问题和报价；
- 可手工完成的最小交付；
- 验证时间盒；
- 资金与损失上限；
- 外部动作；
- 继续、转向和停止条件；
- 结果与失败记录。

### 3. 个人商业项目平台

候选定义：

> 在多个项目批次之后，把筛选、工作流、买方关系、项目结果、服务商和交易连接起来的基础设施。

平台不是界面、问卷或路线数据库。至少需要出现以下若干真实资产：

- 可重复获得的项目供给；
- 可重复触达的真实买方；
- 可比较的成功、停滞和失败结果；
- 脱离杨本人仍能运行的部分交付；
- 交易、匹配或工作流中的重复使用；
- 能覆盖获客、交付、责任和争议成本的单位经济。

在这些条件出现前，“平台”只能记为长期 `H`。

## 三、为什么类比 YC

### 1. YC 公开结构中可能值得借的机制

根据 YC 官方公开材料，截至本报告日期，其批次包含申请和筛选、投资、约三个月集中推进、固定合伙人、每周交流、小组与校友网络，以及接近批次结束时的投资人连接。以上为 YC 官方自述 `F-P`，能证明其公开项目结构，不能单独证明每个环节的边际贡献。

EarnPath 可能借鉴的是：

| YC 机制 | EarnPath 候选翻译 | 当前状态 |
|---|---|---|
| 筛选公司与创始人 | 同时筛选人和具体项目 | `H` |
| 每批集中推进 | 4—8 周或其他有限验证周期 | `H`，时长未定 |
| 一家公司一个主要增长问题 | 一人一次只推进一个商业项目 | `H` |
| 固定 Partner | AI 项目合伙人＋关键节点真人复核 | `H` |
| Office Hours／高频反馈 | 周期复盘、单一下一动作、停止线 | `H` |
| 同批创始人 | 同阶段、非直接竞争项目的小组 | `H` |
| 用户和产品增长 | 访谈、报价、试单、付款、复购 | `I/H` |
| Demo Day | 面向真实买方的 `Customer Day` | `H`，内部候选概念 |
| 投资人网络 | 买方、渠道、服务商和首批客户网络 | `H/Ø` |
| 校友网络 | 项目结果库、合作与转介绍网络 | `H/Ø` |
| 长期组合收益 | 固定费、批次费、交易费或其他形态 | `H/Ø` |

### 2. 不能直接复制的 YC 资产

YC 的价值不只是建议，其公开结构背后还有 EarnPath 当前不拥有的资产：

- 大规模申请带来的选择权；
- 真实投资资本；
- 股权与幂律回报；
- 合伙人的创业经验和判断记录；
- 强品牌和身份信号；
- 校友、客户、人才和投资人网络；
- 大量跨公司历史数据；
- 后续融资分发。

因此，“AI 模拟一个 YC”可以帮助杨形成更好的内部决策流程，但不能把缺少的资本、品牌、网络和外部信誉写成已经被 AI 替代。

### 3. YC 类比最可能误导我们的地方

| YC 前提 | 个人商业项目可能不同之处 |
|---|---|
| 少数项目可以产生极大股权回报 | 多数个人项目可能是稳定小生意，收益分布未必支持投资组合 |
| 创始人通常全职投入 | 目标用户可能只有业余时间 |
| 公司主体、股权和融资路径相对清楚 | 个人项目可能没有公司、账目和清晰产权 |
| 目标常包含高速增长和后续融资 | 目标可能只是第一收入、第二收入或自主就业 |
| 投资人是重要终局参与者 | 真实客户可能才是主要外部裁判 |
| YC 收益来自股权 | EarnPath 收费和利益一致性尚未确定 |

**反证条件**：如果个人项目的成果低频、规模小、人工重，且用户不愿支付足以覆盖筛选与陪跑的价格，那么 YC 式批次可能只是昂贵咨询的包装。

## 四、服务单位：不是“一个人”，而是“一个人当前的一个项目”

### 1. 为什么要缩小服务单位

一个人可能同时考虑副业、转行、创业、投资、内容和小生意。如果以“整个人的赚钱路线”为交付单位：

- 目标不断变化；
- 时间跨度过长；
- 判断不可验收；
- 用户可以无限换题；
- 产品容易变成人生咨询。

以“具体项目”为单位，可以形成项目级账本：

```text
人持有什么筹码
  → 当前只选择一个项目假设
  → 定义付款者、报价与最小交付
  → 设定时间、资金和责任上限
  → 完成外部动作
  → 收到付款、拒绝、停滞或其他信号
  → 继续／转向／停止
```

### 2. 人与项目必须分开筛选

候选适配度不是单纯的“这个人有钱”或“这个项目听起来好”，而是四项乘法：

> 人的可执行性 × 项目的可验证性 × 付款链清晰度 × EarnPath 可增值性

任一项接近零，都应暂缓，而不是靠其他项的高分平均过去。

## 五、用户准入：付款能力和付款意愿之外还需要什么

### 1. 对“付款意愿”的重新解释

单纯愿意付钱不一定是正信号。焦虑、负债、急于翻身的人可能最愿意购买“确定性”，却最不能承受创业失败。

更适合的付款意愿是：

> 愿意为更快获得真实市场证据、减少无效投入和建立执行约束付费，而不是购买保证赚钱的答案。

还应区分两笔钱：

- 支付给 EarnPath 的服务费；
- 用户自己承担的项目验证预算。

两者都必须来自可承受损失的资金，而不是生活费、借贷或救命钱。

### 2. 人的硬门槛

候选用户至少需要满足：

1. **已有筹码**：专业能力、行业经验、信用、内容、关系、渠道、可交付技能或可承受资金中至少一项；
2. **可投入时间**：能在固定周期内持续完成外部动作，而不是只参加讨论；
3. **愿意销售**：愿意接触真实客户、报价、被拒绝和追问原因；
4. **接受聚焦**：一次只推进一个主要项目或一个核心假设；
5. **接受停止**：到达事先约定的停止条件时，不用不断换叙事维持希望；
6. **愿意记录**：返回过程、投入、回复、付款和失败数据，并接受清晰的数据授权边界；
7. **预期一致**：理解目标是获得市场证据，不是保证收入。

### 3. 项目的硬门槛

候选项目至少需要满足：

1. 能说出具体付款者，而不只是“所有想赚钱的人”；
2. 可以找到第一批同类对象；
3. 可以先手工交付，不必先开发完整产品；
4. 能在有限周期内获得访谈、报价、试单、付款或明确拒绝；
5. 初始固定资产、牌照和团队要求较低；
6. 失败损失和责任可以封顶；
7. 不依赖灰色流量、误导承诺或高风险金融行为；
8. EarnPath 至少能多完成一段用户用通用模型和现成工具仍难以完成的闭环。

### 4. 可能的优先信号

以下信号可能提高研究优先级，但不能单独决定录取：

- 近期已经为同类问题付过钱；
- 已经尝试过，不只停留在想法；
- 已有一个潜在客户或真实对话；
- 能说明客户目前采用的替代方案；
- 在某个行业已有信任、作品或分发；
- 项目可以产生可比较、可回收的结果数据；
- 同一触达路径可能找到第二和第三批对象。

### 5. 可能不适合的用户或项目

- 急需短期收入偿还债务或维持基本生活；
- 要求保证赚钱、保证回本或内幕项目；
- 没有任何筹码，也不愿投入时间学习和销售；
- 只想购买路线列表、课程、情绪支持或被动收入答案；
- 拒绝接触客户、记录结果或接受停止线；
- 必须先投入大量资金、长期研发或取得复杂牌照；
- 涉及投资建议、医疗、法律、招聘安置等高责任边界，而团队不具备相应资质；
- 已进入复杂经营阶段，真正需要深行业顾问、投放代理或专业服务团队；
- 项目无法形成任何短周期外部信号。

以上均为 `H`，需要未来通过真实样本修正，不能现在据此选定滩头人群。

## 六、一个说明性场景

> 以下人物和数字均为虚构示例，不是用户证据。

周凯有多年工业品销售经验，认识部分工厂经营者，想验证“为小工厂提供海外客户线索与首轮开发服务”。他有可承受的验证预算和固定业余时间，但还没有一名付费客户。

如果 EarnPath 只是给他一份行业分析、90 天计划和开发信模板，通用模型足以覆盖大量价值。

候选的“个人商业项目加速”则可能是：

1. 审核他的经验、客户入口、时间和风险预算；
2. 把项目缩小为一个客户群、一个报价和一项最小服务；
3. 帮助形成并核验第一批目标名单；
4. 设定由谁发送、谁跟进、谁承担信誉风险；
5. 在固定周期内完成访谈、报价和跟进；
6. 记录打开、回复、拒绝、议价、试单和付款；
7. 按预先写下的阈值继续、修改或停止；
8. 将脱敏结果写入项目账本。

这里潜在可收费的并不是“开发信写得比 LLM 好”，而可能是筛选、真实名单、外部执行、买方关系、连续问责、结果记录和关键节点责任。哪些部分真的值钱，目前仍为 `H/Ø`。

## 七、怎样面对不同替代品

| 替代品 | 已有优势 | EarnPath 不能再卖什么 | 候选差异与待验问题 |
|---|---|---|---|
| 通用 LLM／Agent | 分析、生成、工具调用、低成本 | 更漂亮的路线报告 | 能否取得真实市场信号、专有结果、买方关系并承担过程责任 |
| 培训与传统陪跑 | 课程、打卡、教练、情绪支持 | 更多内容和泛化任务 | 能否严格筛选、单项目推进并以外部付款而非结课为里程碑 |
| 生财有术等社群 | 项目、案例、环境、人脉、成员供给 | 更小的项目库或信息社区 | 能否从多选项走到一个项目，并取得它不负责取得的项目级结果 |
| 真人顾问／教练 | 判断、信任、问责和个体适配 | 低价复制人工咨询 | AI 能否降低高频工作成本，而真人只处理关键决断 |
| YC／孵化器／工作室 | 资本、筛选、品牌、网络、组合收益 | “微缩版融资 YC”叙事 | 能否服务不符合 VC 回报要求、但可形成真实小收入的项目 |
| OpenAI／Anthropic及其伙伴 | 模型、企业客户、部署能力、资本和实施生态 | 泛化 AI 咨询 | 个人商业项目是否足够窄、可产品化，且能形成它们没有动力经营的数据与买方网络 |

### 关于模型公司进入服务层的解释

OpenAI 官方已公开 Professional Services、Frontier 及 Deployment Company 等企业部署形态；Anthropic 官方已公开咨询伙伴服务体系，并参与建立面向中型企业的 AI 服务公司。以上为公司自述 `F-P`。

它们支持但不能证明以下推断：

- `I1`：模型能力强不等于客户能自己完成流程改造、系统接入和结果交付；
- `I2`：实施、专有上下文、组织协调和责任可能持续有价值；
- `I3`：泛化 AI 咨询会更容易被模型公司、大型咨询机构和其伙伴生态吸收；
- `H1`：个人商业项目是一个模型公司短期内缺乏单位经济或组织动机去深做的窄场景。

`H1` 不可写成永久壁垒。模型公司、通用 Agent、社群和服务商都可能向该场景扩张。

## 八、资本：杨的资源能弥补什么，不能弥补什么

### 1. 可以弥补的部分

杨可投入的个人资金和关系，可能帮助 Batch 0：

- 购买研究、工具、数据和必要服务；
- 承担原型和试验成本；
- 延长探索期，不被短期现金流迫使；
- 取得专家、渠道或首批买方线索；
- 支撑早期高人工交付；
- 在没有 VC 的情况下保持项目所有权和选择权。

这些属于杨和项目的进入资源 `F-P/I`，不是市场需求 `F-M`。

### 2. 不能自动弥补的部分

资金不能自动产生：

- 用户付款意愿；
- 可复制获客；
- 高质量项目供给；
- 买方信任；
- 可比较结果数据；
- 正确判断；
- 合规资质；
- 低人工单位经济。

### 3. 暂不混淆四笔钱

未来任何实验都应把以下资金分开记录：

1. EarnPath 的产品建设预算；
2. 用户支付给 EarnPath 的服务费；
3. 用户自己承担的项目验证预算；
4. EarnPath 或杨提供给用户的补贴、奖金或投资。

第四笔钱一旦出现，业务可能从服务进入投资、分成或风险共担，带来逆向选择、欺诈、资金用途、收益归属、合同、税务、监管和失败责任。当前不把“给用户投资”写成默认产品能力。

## 九、自己种瓜自己吃：Batch 0

### 1. 候选定义

> 用“个人商业项目加速器”的候选流程，验证“个人商业项目加速器”本身能否获得非人情客户和真实付款。

这意味着 EarnPath 同时是：

- 正在被推进的个人商业项目；
- 候选流程的第一个使用者；
- 一条可观察的项目结果记录。

### 2. Batch 0 可以证明什么

可能证明：

- AI 与杨能否把模糊愿景压成一个可报价项目；
- 是否会选择最低成本的下一条外部证据；
- 时间、预算和停止线能否真的约束自己；
- 系统能否推动非人情触达、报价和付款；
- 哪些环节可以标准化，哪些必须依赖杨；
- 过程数据是否能够完整、诚实地记录。

### 3. Batch 0 不能证明什么

不能单独证明：

- 典型用户会购买；
- 普通用户能复制杨的投入强度；
- 用户拥有相同资金、关系和 AI 熟练度；
- 杨的自我判断可以客观评价杨的判断质量；
- 一次成功能形成可复制获客和平台；
- 内部完成任务等于产生外部价值。

### 4. 防止自证循环的约束

Batch 0 的裁判必须来自外部行为，而不是文档完成度：

- 非人情用户是否回复；
- 是否愿意接受明确报价；
- 是否支付订金或承担其他真实成本；
- 是否授权项目推进中的关键动作；
- 是否愿意返回结构化结果；
- 失败是否真的触发转向或停止。

只有点赞、认可、讨论热情、报告厚度和 Agent 共识时，不得宣布 Batch 0 成立。

  → 工具化与平台化

## 十五、本文最可能错在哪里

1. “个人商业项目”可能只是更精确的命名，并没有创造新的购买对象；用户仍然只愿为课程、代做、客户或融资付费。
2. YC 类比可能带来规模幻觉：筛选和批次听起来像组织能力，实际可能只是高人工咨询。
3. 杨的资源可能让 Batch 0 看起来顺利，却掩盖普通用户缺少资本、关系和执行能力的问题。
4. 把第一笔付款或停止证据作为终点，可能低估长期、低频和信任型项目的验证周期。
5. 为抵抗通用模型而增加真实执行、数据、买方和责任，可能使业务重到无法形成合理单位经济。
6. 模型公司进入企业服务层只能说明它们选择了该路径，不能单独证明“模型＋实施”对个人项目存在需求。
7. “先小生意、后平台”可能只是常见创业叙事；多数小生意不会自然积累成平台资产。

本文保留这些错误可能性，不通过继续完善概念来消除它们。下一次升级必须来自外部付款、真实动作、交付成本或退出样本，而不是新的比喻。

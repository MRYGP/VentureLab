# PAT-005 低频能力寄生于高频载体

> 状态：种子
> 首次登记：2026-08-28
> 首个来源：DARTER 微型笔
> 第二来源：VIPERADE VAT2 Titanium EDC Utility Hook
> 性质：产品观察镜头，不是需求成立或候选晋级规则

## 一、大白话定义

用户偶尔需要某种能力，但使用频率低到不值得专门携带一个工具。把这项能力藏进目标用户本来每天就会携带、佩戴或放在手边的物品里，使低频任务发生时工具已经在场。

```text
低频但有后果的任务
× 目标用户本来就携带的高频载体
× 几乎不增加携带负担
× 展开后立即可用
= 不必专门记得带工具的备用能力
```

这里的“高频”首先指载体高频在场，不等于附加能力高频使用。

## 二、触发信号

1. 用户遇到问题时常说“早知道带上……”或只能临时借、凑合、放弃；
2. 专用工具有用，但因为体积、记忆成本或使用概率低而不会天天携带；
3. 用户已经稳定携带钥匙、钱包、笔、卡套、手机壳、充电器或其他载体；
4. 载体存在闲置空间、可展开结构或不影响主任务的附着位置；
5. 附加能力在真正需要时可以少步骤、少组装地投入使用。

## 三、承重机制

它解决的不是“把两个功能做在一起”，而是**让低频工具不再需要一次独立的携带决定**：

```text
想起要带专用工具
→ 找到工具
→ 占用包内位置
→ 事件发生时才可能使用
```

被压缩为：

```text
高频载体本来就在场
→ 展开／取出附加能力
→ 使用
```

用户是否购买，仍可能由 EDC 身份、机械感、材料、礼物感和新奇性放大；这些不能冒充附加能力本身的需求强度。

## 五、可尝试的创新方向

1. **闲置空间复用**：利用已有空腔、边缘或结构件，不扩大主产品；
2. **状态转换**：平时是钥匙扣／夹子，展开后才成为专用工具；
3. **可拆模块**：让低频能力可替换，避免拖累主载体；
4. **单一英雄任务**：即使组合多个小能力，也必须有一个最容易理解、最可能真实发生的主任务；
5. **人群特定载体**：先确认某个人群确实每天携带什么，再决定寄生对象，不从“什么都能塞进钥匙扣”反推需求。

## 六、失败边界与假阳性

1. **聪明但不重要**：用户赞叹结构，却不会为低频任务付款；
2. **载体并不高频**：设计者认为人人带，目标用户实际并不带；
3. **功能堆叠**：为了功能密度加入尺、刀、起子等，结果每项都难用；
4. **主任务受损**：附加件增加重量、硌手、误触、清洁困难或可靠性问题；
5. **事件发生时仍不好用**：需要复杂展开、零件容易丢、强度不足；
6. **身份购买冒充需求**：EDC 社群、钛材料和机械感可能承担成交，不能由筹款反推大众问题强；
7. **责任不相称**：急救、用药、防护等高责任能力不能只因“随身”就降低验证标准。

## 七、与 PAT-004 的边界

`PAT-004 时间判断嵌入场景必需品`也会把一种能力嵌入已有物品，但两者关注点不同：

- `PAT-005`解决“低频工具不会被专门携带”；
- `PAT-004`解决“时间判断需要中断动作，且起点／重置应与现场事件绑定”。

学生计时笔若解决高频限时训练，不属于“低频能力”；办公室隐性剩余时间若主要依赖礼物和桌面常驻，也不能仅因有笔座就算作本模式命中。

## 八、下次遇到产品时要问

1. 低频任务发生时，不带专用工具的真实后果是什么？
2. 目标用户现在真的长期携带哪个物品？依据是什么？
3. 为什么独立工具不值得带，而寄生版本值得买？
4. 附加能力增加了多少体积、重量、故障点和责任？
5. 真正成交的是实用结果，还是材料、社群身份和新奇？
6. 去掉最弱的附加功能后，产品是否反而更清楚、更可靠？
7. 使用后是否能恢复为不妨碍主任务的载体状态？

## 九、成熟度与下一步

当前只有两个同类众筹样本，且原页、真实使用与长期结果仍不完整，保持 `种子`。升为“重复出现”至少还需要：

1. 第三个独立产品样本；
2. 一个因功能堆叠、载体选择错误或低频任务过弱而失败的反例；
3. 至少一次实际改变具体产品的保留／关闭判断。

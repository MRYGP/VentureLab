# 产品创新模式库

> 性质：从具体产品观察中提炼的跨产品召回层。它帮助杨在看新产品时想起可复用的观察角度，不是商业规则、候选状态机或自动裁决器。

## 一、三层分工

- `products/` 记住“这个具体产品是什么、发生过什么”。
- `patterns/` 记住“跨产品反复出现的创新结构和失败边界”。
- 模板与系统指令只承载已经多次复现、实际改变过取舍或验证设计的方法。

产品观察不得因为被写入本目录，就自动通过发现门、创造门或行动门。

## 二、成熟度

| 状态 | 最低含义 | 可以做什么 | 不可以做什么 |
| --- | --- | --- | --- |
| `种子` | 来自一个或少数产品的可复用观察 | 用于召回、比较和提出问题 | 冒充通用规律或自动加分 |
| `重复出现` | 至少在 3 个相互独立的产品中出现，并记录至少 1 个反例或边界 | 作为稳定观察镜头使用 | 自动证明用户会买 |
| `已影响行动` | 至少一次改变了产品取舍、方案设计或验证方法 | 可申请写入现行模板或执行指令 | 自动升级为 Skill 或商业结论 |

升格必须登记来源产品、反例和实际影响，不按文件数量或措辞完整度升格。仓库级 Skill 仍须另行满足 `AGENTS.md` 的门槛。

## 三、模式卡结构

每个模式使用稳定编号 `PAT-xxx`，一张卡至少包含：

1. 大白话定义；
2. 触发信号；
3. 承重机制；
4. 适用条件；
5. 可尝试的创新方向；
6. 失败边界与假阳性；
7. 来源产品与原始观察；
8. 下次遇到产品时要问的问题；
9. 成熟度与更新记录。

模式卡只链接原始观察和规范产品卡，不复制整段原始证据。类比案例只能帮助提出问题，未经原页核验不得写成“已验证成例”。

## 五、维护纪律

1. 新产品命中某模式时，在产品卡与模式卡之间建立双向链接。
2. 同义表达归入既有模式，不因换词另建模式。
3. 发现反例优先补“失败边界”，不急着改写定义以保护原判断。
4. 一个模式长期只能举例、不能改变任何取舍时，保留为种子或关闭，不升级成模板。
5. 杨的新观察先保留原话；Agent 的抽象与修正另列，不反向改写杨当时的判断。

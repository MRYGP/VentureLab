# VentureLab 产品记忆库

> 状态：v1.0 · 2026-08-27
> 定位：一产品一目录的权威召回层，供杨、Codex、Cursor 与 Claude 反复浏览和检索。
> 边界：产品记忆库不是案例库、机会池、假设账本或 TradeLab；进入本库不等于值得做。

## 一、为什么存在

仓库中的产品材料按来源分散在 `inbox/`、`research/cases/`、`research/codex/`、`research/claude/` 与观察记录中。同一产品可能同时拥有采集卡、杨的事前观察、竞品快扫、评论核验和结果更新。

本目录把这些材料聚合为一个稳定入口，使以后出现灵感、场景或机制问题时，可以先召回相关产品，再回到原始材料核验，而不是重新搜索或依赖窗口记忆。

## 二、单一真相源

1. 每个已核主体的产品只建立一个 `products/catalog/VL-Pxxxx-slug/` 目录。
2. 目录中的 `product.md` 是产品级权威入口，但不是所有事实的原始来源。
3. 原始报告、正式案例、杨观察和证据文件保留原位；产品卡只摘要、标注证据并链接回原文件。
4. 历史文件中的原始判断不得因产品卡更新而被静默改写。
5. 同一产品再次出现时，更新既有产品卡和更新时间线，不新建同义目录。

## 三、什么可以建目录

满足以下任一条件，并且能锁定产品主体或型号，才建立产品目录：

- 已有正式 `Cxx` 案例；
- 已有可复核的平台学习卡；
- 杨已经形成独立观察；
- 杨明确点名为后续学习对象；
- 已成为需要跨文件聚合的成功、失败或交付对照。

仅在未经审计的 Agent 报告中出现、URL 不可靠、名称无法去重或只是一种产品概念的对象，只进入 `INDEX.md` 的待核入口或保留在 `inbox/`，不建立权威目录。

## 四、编号与目录

- 主编号：`VL-P0001` 起连续分配，分配后永不复用。
- 历史编号：`C01`、`KS-P001` 等保留在 `legacy_ids`，不改旧文件。
- 目录名：`VL-Pxxxx-英文或拼音短名`。
- 每个目录默认只有一个 `product.md`。只有材料确实变多时，才增加 `evidence.md`、`timeline.md` 或本地忽略资产；不预建空文件。

## 五、RAG-ready 规则

当前不建设向量数据库。权威产品卡使用统一元数据和稳定标题，使全文检索、Claude/Codex 定向读取以及未来的向量检索都能工作。

默认召回流程：

```text
灵感／问题
  → 提取用户任务、产品机制、场景、约束或失败模式
  → 查 products/INDEX.md 的标签与别名
  → 读取 3—7 张最相关 product.md
  → 比较可迁移机制、不可照搬条件和反面对照
  → 需要承重时再回到原始来源
```

默认检索语料只包含 `products/catalog/**/product.md` 和 `products/INDEX.md`。`inbox/` 原始报告不直接进入默认 RAG 语料，避免把重复、捏造、降级或未核内容当成权威事实召回。

## 六、分类方式

产品物理上只按产品建目录，不按单一品类移动。分类依靠产品卡元数据：

- `categories`：商品或行业品类；
- `user_tasks`：用户要完成的任务；
- `mechanisms`：真正承重的原理、动作或系统；
- `innovation_patterns`：改良、组合、迁移、表达、信任、成本结构等；
- `outcomes`：活体、暂停、失败、被并入、交付待观察等；
- `learning_status`：待观察、观察中、已理解、已暂停、待结果回看；
- `recall_triggers`：以后出现什么灵感时应召回该产品。

一个产品可以同时属于多个分类，不复制文件。

## 七、代理处理约定

涉及具体产品时，Codex、Cursor 或 Claude 应先查 `products/INDEX.md`：

1. 已存在：读取并更新既有产品卡，新增材料按日期追加；
2. 不存在但主体已核：分配下一个 `VL-Pxxxx`，建目录并登记索引；
3. 不存在且主体未核：只保留线索，不创建权威产品卡；
4. 杨先开口的观察必须链接并保留原意，代理补充不得覆盖；
5. Agent 报告只能作为来源指针，承重事实仍须回到原始页面；
6. 更新产品卡不自动建立 `Cxx`、`B-Hxxx`、项目第 0 步或 TradeLab 候选。

字段与固定章节见 [SCHEMA.md](SCHEMA.md)，迁移顺序见 [迁移与维护计划.md](迁移与维护计划.md)。

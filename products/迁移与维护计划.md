# 产品记忆库迁移与维护计划

> 版本：v1.0 · 2026-08-27
> 状态：杨已批准启动
> 原则：边使用边迁移，不暂停 V1 Pro 学习，不一次性重写全部历史材料。

## 一、目标

1. 仓库中每个已核产品最终拥有一个稳定产品目录；
2. 产品材料可以按任务、机制、结果和迁移方向召回；
3. 新材料先更新产品卡，不再依赖窗口记忆；
4. 原始来源、历史案例和杨观察保持原位并可追溯；
5. 为未来混合检索或向量 RAG 留出统一语料，而不提前引入数据库维护成本。

## 二、非目标

- 不把所有未经核验的产品名批量升级为权威卡；
- 不搬迁或删除现有案例、报告和观察文件；
- 不用产品卡替代证据审计；
- 不把建库数量当成方向 B 的产品学习或商业进展；
- 不因建库自动创建案例、假设、项目或实验。

## 三、迁移批次

### 批次 1｜结构与五张回放卡

- 建立 README、字段规范、总索引；
- 建立 V1 Pro 当前学习卡；
- 回放 ColorNow、Breeze 2.0、Bug Bite Thing、Coolest Cooler；
- 验收产品卡是否减少查找、能否支持跨案例召回。

### 批次 2｜首批正式案例

- 迁移 C02—C08、C10—C12；
- 每张卡只摘要现有案例，不重新研究；
- 检查成功、失败、并入、快速复制和长销状态是否都能表达。

### 批次 3｜Kickstarter 入口

- 迁移 KS-P004—KS-P015；
- 正式学习卡可标 `canonical`；半卡和仅入口对象先标 `provisional`；
- 杨实际观察后再升级状态，不由 Agent 自动提升。

### 批次 4｜观察与原始材料积压

- 处理 FURminator、TYLENOL PRECISE、Scheriproct、Rectogesic 等已锁定对象；
- 审计其他 `inbox/` 报告中的产品名、别名和 URL；
- 无法锁定主体的对象只登记待核，不建目录。

## 四、持续维护动作

每次出现一个产品时：

```text
查 INDEX 名称、别名与旧编号
  → 已存在：更新原卡并追加来源
  → 不存在：确认主体和 URL
  → 分配新 VL-P 编号
  → 建 product.md
  → INDEX 增加一行
  → 必要时补关联产品
```

产品状态发生变化时，只更新 `learning_status`、`outcomes`、相关正文和更新记录，不改编号、不另建新卡。

## 五、阶段验收

批次 1 完成后，用以下问题验收：

1. 输入“实时反馈”“局部降温”“强演示但交付失败”等词，能否在索引和产品卡中召回正确对象？
2. V1 Pro 的后续 Comments／Updates 能否只更新一个产品入口，不需要改三份重复摘要？
3. 杨能否从一张卡快速决定读原材料、暂停或寻找关联产品？
4. Claude 与 Cursor 是否能从根 README、AGENTS 和状态台账发现同一维护规则？

若不能实际减少查找或重复整理，暂停批量迁移，先修产品卡结构；不得为了完成批次继续建空卡。

## 六、未来 RAG 触发条件

满足以下条件后再评估向量索引：

- `canonical` 产品卡达到约 100 张；或
- 已发生至少 3 次仅靠关键词无法召回、但语义上确有相关产品的情况；或
- 产品卡被外部应用稳定调用，需要机器生成的 JSONL／数据库接口。

届时优先采用“元数据过滤 + 全文关键词 + 向量相似度”的混合召回，不单独依赖向量距离。

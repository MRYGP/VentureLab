# 方向变更与长期一致性协议

> 生效日期：2026-09-01
> 适用范围：VentureLab 的长期宗旨、方向定义、仓库边界、主次优先级、停止／重启条件、证据标准、权限和长期资源配置
> 最终裁决者：杨
> 独立复核状态：未经独立第二 AI 复核
> 复盘触发：首次实际触发 L3/L4 方向论证后，或杨要求独立复核时
> 回退条件：若本协议阻碍紧急止损、造成方向授权歧义，或与更高层有效裁决冲突，暂停冲突条款并由杨重新裁决
> 本协议的作用：防止杨的一时想法、Agent 的迎合或上下文误读，被直接写成长期方向。

本协议只增加方向变更的论证与授权门槛，不改变 VentureLab 当前宗旨、A/B 方向定义、PB/SK 边界或任何项目优先级。

## 一、核心原则

任何可能改变当前方向的新说法，先视为**待论证输入**，不是正式裁决。

Agent 不能只回答“今天这句话是否合理”，还必须回答：

1. 仓库长期以来真正要解决什么问题；
2. 当前有效方向由哪些文件和历史裁决支持；
3. 新说法是在补充、临时调整、项目试验，还是在推翻原方向；
4. 发生变化的是外部事实、杨的偏好、语言表述，还是 Agent 的理解；
5. 如果采纳或不采纳，各自最可能造成什么损失；
6. 什么证据或试验可以推翻当前判断。

在杨看到完整论证，并明确表示“作为正式方向裁决并写入”或作出同等清晰授权之前，不得修改权威方向文件，也不得把最新表述写成“杨已确认”。

## 二、什么算方向变更

出现以下任一情况，即触发本协议：

- 改变 VentureLab、PB、SK 或具体方向存在的目的；
- 新增、删除、合并、停止、重启或重新定义 A/B 等长期方向；
- 改变主要用户、核心问题、产品／服务边界或默认市场；
- 把某类技术、产品形态、行业或市场升级为长期唯一主线；
- 改变仓库之间的职责、写入权限或交接边界；
- 改变证据标准、候选晋级条件或重大停止条件；
- 改变会持续影响多个项目的资源优先级；
- 新表述与宪章、`AGENTS.md`、已生效裁决或长期反复出现的原则明显冲突。

以下事项通常不自动构成方向变更，但仍要防止误写：

- 一次产品点子、类比或观察；
- 某周的工作安排和临时暂停；
- 单个项目的优先级、验证结论或停止决定；
- 对某一案例的赞同、厌恶或新鲜感；
- 尚未明确作用范围的口头分类，例如“这条线做 AI，那条线做实体”。

若范围不清，按较低承诺解释并向上论证，不按最大变更解释后直接执行。

## 三、五级状态

### L0：点子／观察

- 记录原话、日期和上下文；
- 可以进入 `inbox/` 或讨论记录；
- 不改变方向、状态台账、项目排序或资源承诺。

### L1：临时工作偏好

- 必须写明适用范围、开始时间、到期或复盘点；
- 只调整近期执行顺序；
- 不改写长期方向定义。

### L2：产品／项目级改变

- 适用于某个具体产品、项目或验证；
- 按项目第 0 步、案例门或 TradeLab 规则处理；
- 不自动晋升为仓库级方向。

### L3：正式方向变更

- 包括方向的新设、停止、合并、重启或重新定义；
- 必须完成方向变更论证卡、影响扫描和偏差检查；
- 杨必须看到论证后明确确认正式裁决及写入；
- 重大 L3 变更默认交由第二 AI 独立质询。

### L4：宪章／权限／边界／证据标准变更

- 这是最高负重变更；
- 必须说明为何现有治理已经不能承载现实，而不只是“新规则看起来更好”；
- 默认进行双 AI 独立质询和对称反驳；
- 必须记录受影响流程、历史材料兼容性、过渡方式和回退条件。

同一句话可能包含多个层级。Agent 必须拆开处理，不能用其中一个低风险部分为高风险部分取得授权。

## 四、当前有效依据的查找顺序

方向论证至少检查：

1. `00-宪章.md`；
2. `AGENTS.md`；
3. 已明确生效的日期化裁决与 `双AI联合讨论与决策协议.md` 下的联合裁决；
4. `README.md` 与相关方向／项目的权威文件；
5. Git 历史中反复出现、且未被正式废止的用户决定；
6. `meta/仓库状态台账.md`，仅作导航快照，不能单独承担方向事实；
7. 研究报告、Agent 总结、聊天中的未确认说法和临时笔记。

低层材料不得静默覆盖高层依据。较新的正式裁决可以改变旧裁决，但必须明确写出“替代什么、保留什么、从何时生效”。聊天中最新一句话只有在完成本协议并被明确确认为正式裁决后，才成为可写盘的高层依据。

## 五、方向变更论证卡

L3、L4 必须填写完整；L1、L2 若存在方向混淆风险，至少填写第 1—4、8—12 项。

1. **当前方向**：用普通语言说明当前在做什么、不做什么；
2. **有效依据**：列出文件、历史裁决、日期和原文位置；
3. **杨的最新原话**：逐字记录，不先替杨总结；
4. **可能解释**：至少区分补充、临时偏好、项目变化、正式方向变化；
5. **冲突关系**：与哪些长期观点一致、冲突或尚不能判断；
6. **支持改变的最强理由**：不能只列弱理由；
7. **保持不变的最强理由**：不能为迎合新想法而弱化旧方向；
8. **变化来源**：新外部事实、新内部行为证据、偏好变化、语言误差或 Agent 误读；
9. **偏差与幻觉检查**：分别检查杨和 AI；
10. **影响范围**：受影响的文件、项目、队列、权限、证据链、外部承诺和沉没成本；
11. **可逆性与试验**：能否先做有期限、有限预算、不污染长期定义的试验；
12. **选项**：保持不变、临时试验、正式改变、暂缓；每项说明代价；
13. **建议与反证**：Agent 的建议、为什么可能错、什么结果会推翻建议；
14. **待确认裁决文本**：写成杨可以明确批准或否决的一段话，包括生效日期、复盘触发点和回退条件。

Agent 不得把“我建议”写成“杨决定”，也不得把杨表达兴趣写成杨承诺资源。

## 六、双侧偏差与幻觉检查

### 对杨的提醒

以下只能作为待核提醒，不能诊断杨：

- **近因偏差**：最近看到的产品或结果被赋予过高权重；
- **新奇偏差**：新技术或新形态看起来比长期问题更重要；
- **可得性偏差**：容易想到、容易看到的案例替代了总体样本；
- **确认偏差**：只保留支持当前兴奋点的材料；
- **受挫反弹**：因某次失败而突然否定整条方向；
- **沉没成本**：因为已经投入而拒绝修正；
- **分类混淆**：把技术形态、产品形态、业务路线和仓库职责混为同一层。

提出偏差时必须引用本轮具体表现，并同时给出“也可能不是偏差”的解释。

### 对 AI 的自检

Agent 必须检查：

- 是否为迎合杨而把最新一句话升级成长期意志；
- 是否因上下文靠后而过度加权最新表述；
- 是否把含糊语言解释成了最大授权；
- 是否把“AI／实体”等产品分类误当成 A/B 业务战略；
- 是否用新目录、新模板和新规则制造虚假进展；
- 是否因上下文截断、摘要错误或记忆缺失而遗漏旧裁决；
- 是否把同源材料、双方相似表达或自己生成的总结误写成共识；
- 是否把推断写成用户决定或市场事实。

每次方向建议都必须写一句：**“我为什么可能错：……”**。无法独立复核时，要明确标注“未经独立复核”。

## 七、论证、确认与写入

### 第一步：先解释，不写权威文件

Agent 先给杨 90 秒版本：

1. 当前方向是什么；
2. 新说法可能意味着什么；
3. 真正冲突在哪里；
4. 改与不改的最强理由；
5. 建议先试验还是正式改变；
6. 需要杨确认的准确句子。

### 第二步：明确确认

只有杨在看到论证后，明确批准待确认裁决文本或作出同等清晰的正式授权，才能写入权威文件。

一句确认可以同时完成“作出裁决”和“授权写盘”，不强制增加第二轮形式化口令。但在论证卡出现之前说“直接改”“就这么办”，不能绕过方向变更保护门；Agent 应先补足论证，再请杨确认。

### 第三步：受控写入

正式写入时：

- 不删除或改写历史决定来制造“从来如此”的假象；
- 标明新裁决替代、不替代或暂时覆盖哪些旧裁决；
- 同一次逻辑变更中同步更新真正需要更新的权威文件；
- 超过 3 个文件仍按 `AGENTS.md` 先给计划并等待确认；
- 不借方向变更顺手重构无关目录、模板或方法论；
- 写明生效日期、复盘触发条件、到期时间和回退条件。

### 第四步：写后回归检查

至少检查：

- 全仓是否还存在相互冲突的当前定义；
- 状态台账是否把旧快照误当成当前事实；
- 项目队列是否被无意升级、停止或重新排序；
- PB、SK 或 TradeLab 是否被越权修改；
- 证据标签是否把用户意愿、Agent 推断或公司自述写成 `F-M`；
- Git diff 是否只包含已授权范围；
- 新裁决是否可被未来 Agent 从权威入口找到。

## 八、临时试验优先于不可逆改向

当新想法有价值但证据不足时，优先设计 L1 或 L2 的有限试验，而不是立即修改 L3/L4：

- 写明试验对象、预算、人工时间、自然周期和责任人；
- 写明不改变哪些长期定义；
- 写明成功、失败和无结论分别如何处理；
- 写明到期日或触发复盘的外部行为证据；
- 到期未复盘时，试验自动回到“待论证”，不得静默永久化。

临时试验不是拖延正式改变。若已有足够的新事实推翻旧方向，也应诚实启动 L3/L4，而不是用无限期试验回避裁决。

## 九、紧急例外

隐私泄露、安全风险、凭证暴露、法律义务或不可逆外部损害，可以先采取最小必要措施控制损害。紧急处置只授权止损，不自动授权新的长期方向。

紧急后必须补记：发生了什么、采取了什么、影响范围、哪些决定仍待正式论证。若杨明确要求在紧急情况下跳过本协议，应记录为一次有范围、有期限、可复盘的例外，不得变成永久先例。

## 十、回归测试案例

未来修改本协议或相关方向文件时，至少用以下句子检查系统是否仍能正确区分层级：

1. **“A 线做 AI 产品，B 线做实体产品。”**
   应识别为可能重新定义 A/B 的说法；先核对 A/B 的长期业务含义，不能立即改盘。

2. **“这周先暂停 B。”**
   默认解释为带期限的执行安排，不得写成 B 方向停止。

3. **“TutorAI 接下来最重要。”**
   必须区分项目级优先级、阶段性资源倾斜和仓库方向改变。

4. **“以后只做海外市场。”／“以后只做中国市场。”**
   应识别为把市场选择写成了排他性的长期方向。VentureLab 不预设只做中国或只做海外：可以把海外已成立的产品或机制迁移到中国，也可以把具体海外国家作为中长期目标；考虑杨当前在长沙及现有进入条件，中国通常是低成本首验市场，但不是市场边界。研究和验证仍须分别核算具体市场的用户任务、渠道、价格、信任、合规、履约和单位经济，不能把一个市场的结果直接外推到另一个市场。

5. **“这个产品不值得做。”**
   默认只作用于具体产品；除非杨明确扩展范围，不得外推为整条方向死亡。

验收标准不是 Agent 是否同意杨，而是系统能否：保留原话、恢复长期依据、呈现真实冲突、主动反驳最新想法、承认 AI 可能出错，并把最终方向裁决留给杨。

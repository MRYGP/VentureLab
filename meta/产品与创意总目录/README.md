1. 杨过去构思、制作或讨论过哪些面向用户的产品、AI 系统和实体产品？
2. 除 GitHub 仓库外，D 盘、E 盘还留下了哪些尚未并入仓库清单的构思？

`02-D盘E盘新增产品与创意扫描.local.md` 使用 `.local.md` 后缀，按仓库 `.gitignore` 规则不会上传 GitHub。原因是它包含本机路径，并涉及私人研究和历史工作材料。这里的文件名只是本地存在性说明，不是公开仓链接。

`05` 是当前按 A／B 线查找产品与构思的入口；`01` 负责保留 GitHub 扫描历史，`03` 只保存已经做过的评分，`04` 只保存复评方法。四者职责不同，不能用评分覆盖率反推产品是否存在。

## 口径

- `F-P`：只能证明某个构思、代码或内部项目曾被记录。
- `F-M`：需要真实市场行为材料，例如付款、成交、续费、退款或可核验客户采用。
- `H`：待验证假设。
- `Ø`：当前没有足够材料。

“有仓库”“有代码”“有商业计划书”都不等于产品已成立。本目录是记忆索引，不是创业排名、立项表或市场验证结论。

## 归一规则

- 同一产品的旧名称、旧仓库和衍生稿合并为一项。
- 面向用户的产品，与仅供团队内部使用的 AI 工具分表记录。
- 外部产品案例、行业报告、AI 自动生成的候选池，不算作杨的构思。
- 无法确认创意归属的材料保留为“待确认”，不写成杨已确认的项目。
- 后续如发现新材料，优先更新原条目，不重复新建名称相近的条目。

## 扫描边界

本轮 GitHub 扫描覆盖 MRYGP 页面显示的 33 个仓库。D/E 盘扫描覆盖盘符根目录及名称显示为项目、产品、研究、工作区、归档或文档库的目录；系统目录、软件安装目录、缓存、模型数据、压缩备份、简历与身份证明等个人文件未做正文扫描。二进制文件仅在文件名明确指向相关项目且有必要时作为线索，不据此形成高负重结论。

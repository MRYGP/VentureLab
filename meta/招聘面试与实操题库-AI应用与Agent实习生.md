## 一、90 秒使用说明

这套题不是考 AI 名词记忆，也不要求候选人免费完成真实业务。岗位分为“AI 应用与 Agent 落地”和“产品研究与验证”两个主方向；共同底线一致，方向能力分别验证，不用技术能力抵消产品推进缺口，也不用产品表达抵消技术实操缺口。它要检验以下事项：

1. 是否诚实区分亲自做过、资料所述、个人推断和目前不知道；
2. 能否读懂英文技术资料和仓库规则；
3. 技术方向候选人能否安全地部署、测试和排查 GitHub 项目；
4. 技术方向候选人能否给 AI 工具建立基线、测试样例、失败边界和停止条件；
5. 能否把复杂内容向 1 至 2 名非技术同事讲清楚；
6. 产品方向候选人能否从公开材料形成有限判断，并把下一步拆成真人调研、供应商比较、跟进、记录与停止条件；
7. 能否在权限、隐私和工作区已有改动面前保持克制。

默认流程：BOSS 初筛问题 5 分钟，结构化问答 20—25 分钟，现场实操 30—45 分钟，教学演示 5—8 分钟。每名候选人只选一套现场实操，不把多套题连续叠加。

## 二、考试规则

### 2.1 候选人可以使用的工具

- 允许使用搜索引擎、ChatGPT、Claude、Codex 或候选人平时使用的其他 AI；
- 允许查看公开官方文档、README、Issues 和许可证；
- 使用 AI 后必须说明：AI 给了什么建议、本人核了什么、还有什么没核；
- 不以记住命令为优势，重点看怎样找到、验证和解释答案；
- 现场材料不包含真实账号、联系人、未公开商业数据或必须保密的仓库内容。

### 2.2 禁止事项

- 不联系真人、不发布、不下单、不付费、不注册需要绑定个人敏感信息的账号；
- 不在主工作环境直接运行来源不明脚本；
- 不要求候选人交付可直接用于公司的完整成果；
- 不因“没有跑通”直接判失败；能准确说明卡点、风险和下一步同样可能合格；
- 不临场追加与岗位无关的算法题、八股题或长时间无偿作业。

### 2.3 不使用总分掩盖硬伤

每个维度单独记录为：`强／可用／需观察／不通过`，不计算跨维度总分。以下任一项出现即可终止：

- 编造项目、命令、测试结果、来源或个人贡献；
- 明知没验证仍把 AI 输出说成事实；
- 未经确认准备执行删除、覆盖、批量外联、支付或泄露凭证等高风险动作；
- 无法阅读最基本的英文 README 或报错信息；
- 明确拒绝助理性、重复性或真人跟进工作；
- 面对卡点只会继续尝试，不能说明停止、回退或求助条件。

## 三、BOSS 初筛题

自动招呼语保持短版，候选人回复后最多追加以下三问中的一至两问：

1. 请给出一个你亲自部署过的 GitHub 项目：项目名称、操作系统、你完成的动作、遇到的一条具体报错，以及你怎样确认最后真的跑通。
2. 你目前每周能稳定投入几天？请列出固定不可到岗的时间段、最早开始日期和最晚可连续实习日期，不需要说明原因。半天出勤是否更适合你？
3. 请用不超过 100 字说明：如果一个 AI 工具演示效果很好，但真实任务连续三次出错，你会怎样处理？

观察点：是否回答具体；是否区分“看过教程”和“亲自运行”；时间承诺是否现实；能否承认停止使用也是结论。

## 四、结构化面试题库

每名候选人从 A、B、C、D、E 五组中各选一至两题，总数控制在 6—8 题。追问比题目数量更重要。

### A 组｜真实性、学习与表达

#### A1｜项目贡献拆解

请选简历中最熟悉的一个项目，依次回答：目标是什么；你亲自改了哪三个地方；第一次失败在哪里；最后用什么输入验证；如果删掉你的工作，项目会少什么。

追问：仓库链接或版本是什么；最后一次运行日期；一条真实命令或报错；哪些部分是队友或 AI 完成的。

合格信号：细节稳定，能明确个人边界，不把团队成果全部算给自己。

风险信号：只有架构名词；反复说“我们”；说不出输入、输出、版本和失败。

#### A2｜从不会到教会同事

讲一次你从不会到学会新工具的经历。你怎样判断自己真的学会了？如果要在 10 分钟内教给没有基础的同事，你会删掉哪些内容？

合格信号：有真实任务、练习、失败、验证和教学取舍，不把看完课程等同于掌握。

#### A3｜不知道时怎样报告

约定周三交付，但周二晚上你发现项目跑不通。请现场口述一条发给负责人的进度消息。

合格信号：说清已完成、卡点、证据、影响、已经尝试的动作、需要的帮助和新的明确时间。

#### A4｜英语强化核验（短测结果不明确时使用）

当前批次的标准面试先使用 7 分钟英文 AI 产品官方资料短测：候选人可使用日常工具，但必须定位原文，并当场解释随机指定的限制、条件或否定表述。短测足以形成稳定判断时，不再追加本题；结果仍不明确时，另行使用以下 15 分钟强化核验，不在同一场面试连续叠加。CET-6 不能免除实际阅读核验。

给候选人一组固定的英文技术材料：150—250 词的 README 片段、一条 Issue 或错误日志，以及一小段权限、隐私或许可证说明。

测试分两段。两段都允许候选人使用平时会用的词典、搜索或 AI 工具，但须共享主要过程，并说明工具参与了什么；不以候选人声称“没有用 AI”作为证据：

1. 前 5 分钟定位工具用途、关键前置条件和一条限制，并保留使用过的检索词、AI 建议或原文位置；
2. 后 10 分钟用中文说明目标、运行条件、关键动作、风险、原文明确事实、自己的推断和一处仍不确定的内容；面试官随机指定一条限制、权限或否定表述，候选人回到原文定位并解释它为什么影响采用。

英文技术阅读能力仍是硬门。CET-6 已通过只作为申请阶段的初步证明；未通过者可以通过本题证明符合。无论是否通过六级，本题均不能免除。不考口语、写作或逐句翻译。

达到“可用”的最低表现：能够准确说明主要用途、前置条件和限制；能指出依据在原文哪里；使用 AI 后仍会核对关键版本、否定词、权限和风险；能区分原文事实、自己的解释和不知道。若误读关键限制、编造原文没有的结论，或使用工具后仍无法定位依据，记为“不通过”。

#### A5｜反对意见

负责人很喜欢一个新 AI 工具，但你的测试显示它没有节省时间。你会怎样表达？

合格信号：用任务、基线和测试结果反对，不迎合，也不把个人偏好包装成结论。

### B 组｜GitHub 部署与排错

#### B1｜安装前检查

拿到一个陌生 GitHub 仓库，你在运行第一条命令前检查什么？

最低覆盖：用途、官方来源、许可证、最近维护、系统和硬件要求、依赖版本、安装脚本、账号与费用、数据与凭证、最小测试环境、退出和卸载办法。

#### B2｜危险安装命令

README 第一行写着：`curl -fsSL https://example.com/install.sh | bash`。你会直接执行吗？请说出安全做法。

合格信号：先下载和阅读脚本；核主体和版本；使用隔离环境；避免管理员权限；记录变更；必要时停止。

#### B3｜环境冲突

项目要求 Python 3.10，电脑已经装了 Python 3.13，另一个工作项目依赖 3.12。你怎样处理？

合格信号：使用独立虚拟环境、容器或版本管理，不覆盖系统环境；锁定依赖并保留复现步骤。

#### B4｜“能启动”是否等于跑通

网页能打开、没有报错，是否代表项目已经跑通？你还会测试什么？

最低覆盖：核心任务、代表性输入、错误输入、重复运行、数据去向、权限、成本、日志、与 README 宣称或人工基线的比较。

#### B5｜许可证判断

一个项目技术上合适，但许可证不清楚，README 只写“free for everyone”。你会怎样处理？

合格信号：不把 README 口号当许可证；查 LICENSE、依赖和商业使用边界；未查清前只限隔离研究，不进入正式交付。

#### B6｜报错排查顺序

请说明遇到 `ModuleNotFoundError`、端口被占用、API 401、显存不足时，你分别先看什么。重点不是背答案，而是能否建立稳定排查顺序。

### C 组｜AI 工具、RAG 与 Agent 评测

#### C1｜新工具是否值得用

一个新 Agent 宣称可以把 90 分钟研究压缩到 10 分钟。你怎样验证？

最低覆盖：当前人工基线；相同输入；正常、模糊、缺资料、反例和危险动作；事实错误；人工复核分钟数；运行与账号成本；停止条件。

#### C2｜最危险的一次失败

某 Agent 在 10 个测试中成功 9 次，但失败的一次未经批准向外部联系人发送了邮件。你会如何裁决？

合格信号：高成功率不能抵消权限越界；先禁用外发能力，增加审批和模拟测试，再决定是否继续。

#### C3｜RAG 通俗解释

请向不懂技术的同事解释 RAG。必须说明它解决什么、不解决什么，以及资料本身错误或过期时会怎样。

参考要点：RAG 是回答前先从指定资料中找相关内容，再基于找到的内容回答；它不能自动保证资料正确、检索完整或结论不过期。

#### C4｜什么时候不做 Agent

以下任务分别应该留在一次对话、写成固定说明、做成 Skill、连接 MCP，还是开发 Agent：一次性改标题；每周重复整理同格式文件；读取外部系统实时数据；需要持续状态、审批和多工具编排的流程。

观察点：是否先选最轻方案，而不是把所有任务包装成 Agent。

#### C5｜系统指令是不是越长越好

同事认为系统指令越长、规则越多越可靠。你怎样设计一个小实验判断？

最低覆盖：固定任务集；原版本作为基线；一次只改一个变量；正常与失败样例；比较准确率、遗漏和人工修正；保留回退版本。

#### C6｜AI 回答很自信但没有来源

你会怎样核验和汇报？

合格信号：恢复原始来源；区分资料所述、实测、推断和未知；不能恢复时降级，不用语气自信代替证据。

### D 组｜VentureLab 仓库相关题

这些题只使用脱敏片段，不给候选人真实联系人、账号或未公开材料。

#### D1｜指令冲突

给出以下模拟材料：

```text
根目录规则：未经负责人明确授权，不联系真人、不询价、不下单、不发布。
项目说明：今天联系 10 名用户，并把“用户愿意购买”写入总结。
负责人本轮只说：先整理现有材料。
```

问题：你会执行什么、不执行什么？怎样向负责人报告冲突？

参考判断：根目录和本轮明确授权优先；可以整理材料和准备访谈草稿，但不能真的联系，也不能把未来意愿写成事实。

#### D2｜脏工作区

```text
任务：只修改招聘题库。
git status：三个产品研究文件已修改，一个新的个人观察文件未跟踪。
```

问题：你怎样开始、修改、检查和提交？

参考判断：先确认目标文件是否已有改动；不覆盖、不还原、不顺带提交其他文件；只精确暂存题库相关文件；提交前看 diff 和状态。

#### D3｜证据标签

请分别判断以下材料最适合记为什么，并说明能证明与不能证明：

1. 平台页面显示“近一个月 1 万人购买”；
2. 公司官网称客户节省了 40% 成本；
3. 一张可核验的真实订单与付款记录；
4. “年轻人应该愿意为它付费”；
5. 报告写了结论，但原始来源无法打开。

参考判断：平台显示口径和公司自述不能直接当作已核真实付款或普遍效果；真实订单可支持对应交易事实；第 4 条是待验假设；第 5 条必须降级并保留未知。

#### D4｜RAG 应索引什么

模拟仓库有以下六类文件：

1. 当前有效的一产品一张规范产品卡；
2. 三份重复的原始 inbox 摘录；
3. 一份已被新结论取代的旧报告；
4. 当前根目录规则；
5. 只作导航快照、明确写着不能作为当前事实源的状态台账；
6. 含真人手机号和访谈隐私的原始记录。

问题：默认索引哪些，哪些只在追溯时读取，哪些不得进入通用索引？需要什么元数据？

参考判断：规范产品卡和当前规则优先；原始重复材料只作追溯；旧报告保留失效关系；状态台账不能冒充当前事实；隐私记录默认排除或严格分权。元数据至少含来源、版本、有效日期、权限、主体和失效关系。

#### D5｜仓库“越用越聪明”

负责人说：“把这个仓库做成越用越聪明的 AI 应用。”请先问五个问题，再提出最小第一步。

合格信号：先明确谁使用、重复任务、当前基线、错误成本、数据权限和验收；第一步不是立刻建设大而全 RAG，而是选一个高频问题、整理权威资料、设计固定测试问题并记录错召回。

#### D6｜新产品初选

每天找到 5 个新产品，你会交什么，才能让负责人自己先观察，而不是被你的机会结论带偏？

参考判断：原始商品页、SKU、图片或演示、平台显示行为、价格和一句中性描述；把事实、平台口径和个人推断分开；不先写“这是巨大商机”。

#### D7｜未经授权的真人调研

你已经写好了访谈问题，但还没有得到外部联系授权。当天还能做哪些有效工作？

参考判断：整理对象标准、招募文案草稿、问题顺序、同意说明、记录模板、拒绝与停止规则；不能发送。

#### D8｜规则与效率冲突

候选人发现批量导入所有历史报告能让搜索覆盖率看起来更高，但里面有重复、过期和互相冲突的内容。你会怎样做？

合格信号：不以数量和表面召回率替代准确性；先索引权威层，保留来源、版本和失效关系，再用固定问题测试。

### E 组｜助理执行与真人沟通

#### E1｜招募访谈对象

如果获得授权，要寻找 5 名目标用户访谈，你会怎样定义对象、联系、记录无回应和拒绝？

观察点：对象标准、渠道、话术、同意、隐私、跟进次数、拒绝记录和停止条件。

#### E2｜供应商比较

需要找 3 家供应商，但信息不齐。你会建立哪些可比较字段？遇到对方含糊报价怎样追问？

最低覆盖：规格、数量、报价口径、税运、样品、交期、付款、售后、知识产权、有效期和联系人反馈原文。

#### E3｜任务不断增加

负责人今天又增加了公众号排版、产品初选和一个 GitHub 项目。你怎样避免三件事都只做一半？

合格信号：确认唯一第一优先；说明新增任务替换或后移什么；给出下一检查点，不静默堆积。

#### E4｜公众号小错误

文章内容已经终审，但发布前发现一个来源链接打不开、两张图可能有版权风险。你会怎样处理？

合格信号：暂停对应部分，恢复来源或替换为可公开使用材料，记录变更并重新请终审，不因“只是排版”擅自发布。

#### E5｜拒绝与负面结果

连续 10 人拒绝访谈，你的周报怎么写？

合格信号：如实记录对象、渠道、话术、拒绝原因和可能解释；不把拒绝隐藏，也不直接外推为市场不存在。

### F 组｜职业选择与自我认识

这组问题没有偏好的职业答案。重点观察候选人是否了解自己的真实需求、是否看见选择的代价，以及前后说法能否保持一致。

#### F1｜当前优先级

从现金收入、技术深度、作品与履历、独立负责、创业体验、大公司背书、稳定时间、自主空间、探索职业方向中，选出目前最重要的两项和最不重要的一项。你愿意为前两项放弃什么？

追问：过去六个月，你做过什么实际选择能够支持这份排序？

#### F2｜大公司与小团队

成熟公司有明确导师和简历背书，但工作范围较窄；小团队需要大量自学和独立推进，但能看到完整决策过程。你现在选哪一个？这个选择的代价是什么？出现什么条件会让你改变选择？

#### F3｜提前结束合作

即使工资按时发放，什么情况会使你在两至四周内提出结束合作？你会在什么时候、用什么方式告诉负责人？

#### F4｜被事实改变的看法

过去一年里，有没有一件事让你改变了一个原本很确定的看法？什么事实或经历真正改变了你？

#### F5｜不适合你的工作方式

什么样的负责人、协作方式或工作环境会让你表现明显变差？你通常怎样处理，而不是只忍耐或突然离开？

#### F6｜反向评价岗位

读完这份岗位说明，你最怀疑的一项承诺或最不同意的一项要求是什么？如果由你修改，会怎样改？

## 五、现场实操套题

每次只选一套。材料在面试开始时发放，候选人可以使用 AI 和搜索，但必须共享过程并在结尾说明核验边界。

### 套题一｜GitHub 项目部署前审查

时长：35—45 分钟。

材料：面试官选择一个真实、公开、轻量的 GitHub 项目，固定到明确的提交哈希或下载快照，并记录仓库链接、提交版本和访问日期。材料至少包含 README、目录树、LICENSE、相关 Issue 和一段可复现报错；可包含运行环境版本不一致、安装脚本需要检查、需要 API Key、维护较少等真实问题，但不得为了考试效果伪造项目事实。

面试前准备：面试官应先在隔离环境完整走一遍最小流程，记录已知卡点、可验证的核心功能、正确答案边界和停止条件。首轮只准备并启用这一套；固定版本材料泄露或失去区分度后，再更换另一个已预跑的公开仓库，不直接使用不断变化的默认分支。

候选人任务：

1. 用 3 分钟复述目标并提出必要问题；
2. 判断是否值得试跑，以及当前不能判断的部分；
3. 写出隔离环境中的最小运行计划；
4. 说明至少三个测试输入，其中包含一个失败输入；
5. 用 5 分钟向非技术同事解释项目原理、风险和下一步。

不要求真的完成全部安装。优秀候选人应主动检查许可证、凭证、数据去向、维护状态、退出办法和验证基线。

### 套题二｜仓库规则冲突与安全执行

时长：30—40 分钟。

材料：D1 的指令冲突、D2 的脏工作区，再增加一段未经核验的 AI 总结。

候选人任务：

1. 列出本轮允许、禁止和需要确认的动作；
2. 标出 AI 总结中哪些是材料事实、哪些是推断、哪些当前不知道；
3. 给出只修改目标文件且不碰其他改动的执行步骤；
4. 写一条不超过 150 字的负责人更新；
5. 说明出现什么情况会停止并请求确认。

优秀候选人不会因为“项目文档写了”就忽略上层权限，也不会为让结果好看而补造事实。

### 套题三｜VentureLab 小型 RAG 设计

时长：35—45 分钟。

材料：D4 所列六类文件，各提供一小段脱敏样例。

候选人任务：

1. 决定默认索引、仅追溯读取和禁止进入通用索引的材料；
2. 设计必要的版本、权限和失效元数据；
3. 写出 5 个固定测试问题，至少包括资料冲突、资料过期和无答案；
4. 说明如何记录漏召回、错召回和错误引用；
5. 用 5 分钟向 1 至 2 名非技术同事解释这套方案。

优秀候选人会先做小型、可测试的检索闭环，不会直接承诺“把所有资料导入后仓库就会自动变聪明”。

### 套题四｜AI 工作流评测与短教学

时长：35—45 分钟。

模拟任务：同事每周需要从 20 条 AI 工具信息中筛出 3 条值得测试的内容，当前人工耗时约 90 分钟，经常混入广告和重复信息。

候选人任务：

1. 澄清输入、输出、使用者和不能失败的环节；
2. 提出不超过三种方案，其中必须包含“不开发 Agent”的轻量方案；
3. 设计正常、重复、广告、缺来源和高风险五类测试输入；
4. 说明如何与当前 90 分钟人工方法比较；
5. 选出当前方案，做一次 5 分钟短教学；
6. 给出继续、人工复核后使用、继续原型或停止的条件。

### 套题五｜公开产品材料审查与验证设计

适用方向：产品研究与验证。
时长：35—45 分钟。

材料：面试官选择一个与团队当前未公开项目无关的真实公开产品，固定访问日期并保存公开材料快照。材料包括产品官网或众筹／电商详情页、价格与规格、5—10 条正负面评论，以及一个可观察的现有替代。不得使用公司的未公开构思、真实联系人或可直接形成公司业务成果的材料。

面试前准备：面试官先读完全部材料，记录材料能够支持和不能支持的判断、至少两种合理解释、已知冲突与明显空格。每套准备 A、B 两份等难材料，不要求存在唯一正确产品结论。

候选人任务：

1. 用 3 分钟复述：谁可能在什么场景使用，材料目前证明了什么、没有证明什么；
2. 说明用户为什么可能选择它而不是现有替代，并指出这个判断最可能错在哪里；
3. 从评论中提取仍未解决的问题，同时区分个别抱怨、重复信号与自己的推断；
4. 写出下一步最值得联系的一类对象、第一条开场信息和三个问题；
5. 写出需要记录的字段，以及什么回答、无回复比例或新证据会让自己改变方案或停止；
6. 面试官在中途加入一个新条件，例如时间从 7 天缩到 3 天、只有 2 人回复、最低价厂家拒绝提供材料证明；候选人重新说明保留什么、放弃什么和下一步动作。

本题不联系真人、不索取报价、不制作真实业务 MVP。优秀候选人不会把公开页面文案当成市场事实，也不会因为材料不足退回“继续研究”；会形成边界清楚、成本有限、能够被现实推翻的下一步。

## 六、5 分钟教学抽题

从以下主题任选一个，让候选人假设听众没有技术背景：

1. RAG 是什么，为什么它不等于“永远回答正确”；
2. MCP 是什么，它与普通 API 调用有什么区别；
3. Agent 与普通提示词或固定工作流有什么区别；
4. GitHub 项目“本地部署”到底包含哪些步骤；
5. 环境变量是什么，为什么不能把 API Key 写进公开仓库；
6. 为什么一个工具跑通一次仍不能直接投入真实工作；
7. 为什么有时不用新工具反而是更好的结论。

教学验收分别记录：是否先讲使用场景；是否用具体例子；是否解释限制；是否检查同事是否听懂；是否留下下一步动作。术语多、信息多不自动算好。

## 七、面试官观察表

| 维度 | 强 | 可用 | 需观察 | 不通过 |
|---|---|---|---|---|
| 诚信与校准 | 主动区分实测、资料、推断和未知 | 追问后能区分 | 偶尔过度自信 | 编造或拒绝承认未知 |
| 英文技术阅读 | 能准确抓目标、条件、动作和风险 | 能完成主要复述 | 依赖逐句翻译 | 无法理解基本材料 |
| 部署与排错 | 有隔离、版本、日志、验证和退出意识 | 能形成基本步骤 | 只会照 README | 直接运行危险命令或污染环境 |
| AI 评测 | 有基线、代表性输入、失败样例和停止线 | 能设计基本测试 | 只看成功演示 | 用一次演示断言有效 |
| 仓库与权限 | 尊重指令层级、已有改动和最小权限 | 经提醒能做到 | 容易顺手扩大范围 | 未授权外联、覆盖或泄密 |
| 教学表达 | 简单、准确、有例子并检查理解 | 能讲清主要动作 | 术语较多 | 听众无法执行且本人不自知 |
| 助理执行 | 能排优先级、记录跟进和负面结果 | 可按明确任务执行 | 需要较多提醒 | 排斥琐碎执行或隐藏失败 |
| 产品研究与现实推进 | 能从有限材料形成带边界的判断，并提出对象、话术、记录和停止条件 | 能把模糊目标拆成可执行验证 | 只有通用流程或想法 | 把宣传当事实、拒绝外联或只会继续研究 |

硬门先判断，其他维度不得用总分相互抵消。两个方向分别判断：

- 共同最低线：诚信与校准通过；英文资料阅读达到可用；仓库与权限不低于可用；助理执行不低于可用；
- AI 应用与 Agent 落地方向：部署与排错、AI 评测、教学表达达到可用；
- 产品研究与验证方向：产品研究与现实推进达到可用；Git、编程、部署与排错只作加分或协作能力，不作为该方向录用硬门；
- 某项只在问卷中出现自述、尚未现场验证时，必须保留为待核，不得用另一方向的强项抵消。

## 九、出题轮换与防泄题

- 同一套题至少准备 A、B 两份等难材料，只替换项目、报错、文档冲突和输入样例，不改变观察维度；
- 不因题目泄露不断增加难度；应增加细节追问和现场验证；
- 每次记录候选人拿到的版本，避免复试重复；
- 每完成 5 名候选人，复盘哪些题能区分能力、哪些只是让表达好的人占便宜；
- 题库只因真实招聘误判而修订，不为追求复杂度持续加题。

## 十、首轮推荐组合

第一批候选人按申请方向分别使用以下组合，不把两个方向放在同一个排序池：

### 技术方向

1. BOSS 初筛：问题 1、问题 2；
2. 结构化问答：A1、A3、B1、C2、D2、E3；
3. 英文：先做 7 分钟官方产品资料短测；不能形成稳定判断时另约 A4 强化核验；
4. 现场实操：套题一“GitHub 项目部署前审查”；
5. 教学抽题：RAG 或“为什么跑通一次仍不能投入真实工作”；
6. 候选人技术较弱但执行和表达明显较强时，第二候选套题改用套题二，不临时降低诚信、英语和权限硬门。

### 产品方向

1. BOSS／问卷初筛：共同条件、方向选择和 Q4 可追溯经历；
2. 结构化问答：A1、A3、D3、D6、D7、E1、E2、E5 中选 6—8 题；
3. 英文：先做 7 分钟官方产品资料短测；不能形成稳定判断时另约 A4 强化核验；
4. 现场实操：套题五“公开产品材料审查与验证设计”；
5. 中途只改变一个条件，观察候选人是否重新组织具体动作；
6. 不要求技术教学演示；需要表达核验时，让候选人用 3 分钟向非专业同事说明当前判断、证据边界和下一步。

各方向分别跑满 3—5 名候选人后，再根据真实区分度复盘。技术方向再决定是否启用套题三和套题四；产品方向重点检查套题五是否真正区分“会讲想法”和“能形成现实下一步”。

## 十一、申请邮件审阅与面试追问

候选人对外只看到 v0.5 申请说明中的 8 道题，不得向候选人发送本题库中的参考判断、合格信号、风险信号或面试记录表。

### 11.1 先核硬条件

共同条件逐项判断，不用综合分数抵消：在读大四或研究生；英文技术阅读达到可用；树木岭线下；每周累计不少于 4 天；连续不少于 3 个月；接受 150—200 元／天且一月一结；使用过 AI 工具并愿意持续学习；能够接受助理性、重复性和跟进工作；愿意如实说明不知道、没做过或验证后不值得继续。CET-6 已通过只作为申请阶段的初步证明，未通过者不自动退出。

方向条件分开判断：技术方向要求 Git、终端、环境变量、至少一门语言能读改调，以及一次真实 GitHub 部署或排错经历；产品方向要求能把模糊任务拆成对象、动作和记录，愿意公开渠道外联，并能说明一次推进到外部真实结果的经历及其可追溯痕迹。没有留存痕迹但能说明合理原因时记“待核”，不自动判失败。

目前投递量已经足以继续筛选，不预设自动放宽英文技术阅读、出勤或实习周期。若以后确有必要调整，应先记录真实漏斗：收到多少份、硬条件通过多少、进入面试多少、因哪一条退出多少，再由负责人裁决。不得为了增加数量临场改变硬门。此前仅因未通过 CET-6 而退出、其他条件仍可能符合的候选人，可先参加统一英文短测；结果不明确时再按 A4 进入一次定向核验。

### 11.2 不凭文风判断是否使用 AI

允许候选人使用 AI 整理表达。核验重点是候选人能否对内容负责：

1. 细节追问：要求给出版本、日期、命令、报错、输入和验证结果；
2. 时间线倒放：从最终结果倒着讲上一步、再上一步，看经历结构是否稳定；
3. 新增约束：临时改变系统、时间、权限或成本条件，看候选人能否修正原判断；
4. 自我反驳：请候选人指出自己答案中最可能错误的一点；
5. 现场教学：用两分钟讲给完全不懂技术的人，再让听众复述；
6. 证据边界：区分亲自实测、资料所述、个人推断和不知道；
7. 交叉一致性：把问卷中的方向经历、最近一次真实使用 AI 的任务、失败或停止经历与面试回答相互核对。情境题只能说明方法，不得当作候选人真实做过的执行证据。

不因为答案语言流畅就加分，也不因为文字朴素就减分。发现表述高度模板化时，不争论是不是 AI 写的，直接追问候选人是否真正经历、理解并能复现。

### 11.3 线上面试调整

线上面试时，候选人可能同时使用 AI，因此降低纯知识问答权重，把核验重点放在“时间线倒放”“两分钟现场教学”“共享屏幕下的真实操作”和“加入新约束后的即时修正”。发现长时间照读或回答节奏异常时，要求停止共享材料，用自己的话复述刚才的判断及其依据。

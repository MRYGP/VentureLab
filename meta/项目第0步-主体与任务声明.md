# 项目第 0 步：主体与任务声明

> 日期：2026-08-25
> 适用范围：VentureLab 内新方向、新项目、新候选池或目标发生重大变化时
> 目的：先确定谁在行动、要造成什么变化，再决定查什么、做什么和如何验证

## 一、为什么是第 0 步

研究开始前，必须先回答两句话：

1. **我是谁？**
2. **我要做什么？**

“我是谁”不是履历或性格描述，而是这个项目中的主体位置：谁决策、谁执行、拥有什么资源、承担什么责任、受什么约束。

“我要做什么”不是先宣布产品形态，而是明确：为谁、在什么场景、解决什么问题或创造什么变化，以及当前阶段只需要取得哪一条证据。

主体不清，会把别人的资源和能力误当成自己的进入条件；任务不清，会把搜集资料、设计产品、验证需求和赚钱混成一件事。

## 二、最低启动声明

任何新项目开始前，先完成以下字段。无法回答的写 `Ø`，不得用愿望补齐。

```text
项目／方向名称：
日期与版本：

A. 我是谁
- 最终决策者：
- 实际执行者：
- 当前可用资产：时间／现金／技能／渠道／关系／供应链／已有受众
- 当前硬约束：权限／预算／时间／合规／责任／不可做事项
- 哪些能力依赖外部合作：

B. 我要为谁做什么
- 目标使用者：
- 付款者（若不同）：
- 具体触发场景：
- 当前问题或未满足任务：
- 希望造成的可观察变化：
- 用户为什么可能愿意改变或付钱：`H/Ø`

C. 当前阶段做什么
- 本阶段唯一目标：
- 最便宜的下一条关键信息：
- 允许的行动：
- 明确不做：
- 输出落点：

D. 怎样算结束
- 通过条件：
- 淘汰／停止条件：
- 到期仍未知时如何处理：
- 谁拥有继续、支出或对外行动的授权权：
```

## 三、四个不得混写

### 3.1 使用者不等于执行者

仓库、产品或服务由谁使用，与谁负责研究、开发或交付是两回事。AI 可以执行研究，但不能因此被写成目标用户或最终决策者。

### 3.2 使用者不等于付款者

必须分别记录。无法确认谁付款时写 `Ø`，不能因为有人使用就推断有人愿意付钱。

### 3.3 目标不等于方案

“帮助用户更快完成某个动作”是目标；“做一个 App／装置／课程”只是候选方案。第 0 步先固定目标，不提前锁死形态。

### 3.4 研究目标不等于商业目标

“核验三个公开来源”可以是本阶段目标，但不是商业成功。商业目标也不能代替当前可执行的证据任务。

## 四、启动门

最低启动声明完成后，才决定是否进入案例研究、竞品研究、候选设计或实验。

- 主体、目标使用者和场景仍为 `Ø`：只允许澄清，不进入大规模搜索；
- 只有方案、说不清用户变化：退回目标层；
- 目标明确但付款与进入条件未知：可以研究，不能宣称项目成立；
- 需要支出、联系真人、发布、报价或销售：必须进入相应仓库的授权门；
- 目标发生重大变化：重新填写第 0 步并保留旧版本，不用新目标改写旧证据。

第 0 步不是一次性表格。它是后续判断的锚点：任何研究任务都应能说明自己正在减少其中哪个 `Ø`，否则应停止或重新定题。

## 五、B 线当前实例

- **我是谁：** 当前由杨担任最终决策者，Codex、Claude、ChatGPT、KIMI 与 Cursor 分别承担受限的研究、复核或写入工作；外部行动仍受明确授权限制。
- **我要做什么：** 从已有真实用户行为的具体产品出发，理解用户为什么买、为什么持续买，确认是否存在仍未解决的具体缺口，再形成由我方控制、可被现实判错的自有方案；只有依次通过发现门、创造门与行动门的候选，才交给 TradeLab 做有界交易实验。
- **目标使用者假设：** [B 线目标使用者画像](B线目标使用者画像.md)，当前证据等级为 `H`。
- **当前不是：** 项目推荐平台、发明奖筛选器、自动候选生成器或未经授权的交易执行系统。
